Framing & Error Control

The Data Link Layer transforms raw physical bitstreams into discrete, manageable units called frames and ensures reliable transmission via Error Detection (Parity, Checksum, CRC) and Correction (Hamming Code).

Section 12.1

Framing Techniques

The Physical Layer delivers raw bits without structure. The Data Link Layer divides this bit stream into distinct **Frames**. Framing allows the receiver to detect where a frame begins and ends.

Major Framing Methods

  • Character Count: Header specifies the number of characters in the frame. (Disadvantage: If count byte is corrupted, synchronization is completely lost).
  • Byte Stuffing: Delimits frames using special Flag Bytes (e.g., FLAG byte at start and end).
  • Bit Stuffing: Delimits frames using special Bit Pattern (e.g., 01111110 flag).
  • Physical Layer Coding Violations: Used in networks like Token Ring/LANs where signal encoding has unused states (e.g., Manchester encoding high-high or low-low pairs).

Section 12.2

Character / Byte Stuffing

In Byte Stuffing, special delimiter bytes called FLAG mark the start and end of a frame. If the user data itself contains the FLAG byte, an Escape Byte (ESC) is inserted ("stuffed") before it so the receiver knows it is part of data, not a frame boundary.

📌
Byte Stuffing Rules
• Data has FLAG → Transmitted as ESC FLAG
• Data has ESC → Transmitted as ESC ESC
• Receiver strips the first ESC byte upon arrival.

Section 12.3

Bit Stuffing

In Bit Stuffing, frames begin and end with a special 8-bit flag pattern: 01111110 (six consecutive 1s).

Rule: Whenever the sender's data stream contains five consecutive 1s, the sender automatically stuffs a 0 bit immediately after them. The receiver automatically removes ("unstuffs") any 0 bit that immediately follows five consecutive 1s.

Section 12.4

Error Detection vs Correction Overview

Network signals suffer from noise, causing bits to flip (0 → 1 or 1 → 0).

  • Single-Bit Error: Only one bit of a given data unit is altered.
  • Burst Error: Two or more bits in the data unit are altered (common in wireless / impulse noise).
  • Error Detection: Detecting that errors exist, then requesting retransmission (ARQ).
  • Error Correction: Detecting errors and determining exact bit locations to fix them automatically without retransmission (Forward Error Correction - FEC).
Hamming Distance d(x,y): Number of bit positions in which two codewords differ.
• To DETECT 's' errors: Min Hamming Distance dmin ≥ s + 1
• To CORRECT 't' errors: Min Hamming Distance dmin ≥ 2t + 1
🔢
Section 12.5

Parity Check (1D & 2D)

In Simple Parity Check, a redundant parity bit is appended to the data unit so that the total number of 1s becomes even (Even Parity) or odd (Odd Parity). Can only detect odd numbers of bit errors (fails if 2 bits flip).

In 2D (Two-Dimensional) Parity Check, data is arranged in a grid, and parity bits are calculated for every row AND every column. Can detect burst errors and correct single-bit errors.

➕
Section 12.6

Checksum

Used extensively in Internet protocols (IP, TCP, UDP). Data is divided into k segments of n bits each. The segments are added together using **1's complement addition**, and the 1's complement of the sum becomes the Checksum appended to the data.

At receiver: Add all received segments including checksum. If result is all 1s (0xFFFF), data is valid.

⚙️
Section 12.7

Cyclic Redundancy Check (CRC)

CRC is a powerful error detection method based on **binary polynomial division** (using XOR operation without carry).

CRC Algorithm Steps

  1. Given a Generator polynomial G(x) of degree r, append r zero bits to the original data D.
  2. Divide the padded data (D · 2r) by the divisor G using modulo-2 (XOR) division.
  3. The remainder of size r bits is the CRC Checksum.
  4. Replace the r padded zero bits with the CRC remainder and transmit the frame.
  5. Receiver divides received frame by G. If remainder is 0, frame is error-free.
Example: Data = 1010000, Divisor G = 1001 (degree r = 3)
Padded Data = 1010000 000
XOR Division Remainder = 011
Transmitted Frame = 1010000 011

Section 12.8

Hamming Code Error Correction

Hamming Code is a Forward Error Correction (FEC) technique invented by Richard Hamming. It can detect up to 2-bit errors and correct single-bit errors by adding redundant parity bits at positions that are powers of 2 (1, 2, 4, 8, 16...).

🧮
Redundant Bits Formula
If data has m bits and we add r redundant bits, the relationship is:
2r ≥ m + r + 1
Example: For 4 data bits (m = 4), we need r = 3 redundant bits (since 23 = 8 ≥ 4 + 3 + 1 = 8).
Total codeword length = 7 bits (Hamming 7,4 Code).

Bit Placement for Hamming (7,4) Code

Parity Bit Calculations:

  • P1 checks bits 1, 3, 5, 7 (positions with LSB bit 1)
  • P2 checks bits 2, 3, 6, 7 (positions with 2nd bit 1)
  • P4 checks bits 4, 5, 6, 7 (positions with 3rd bit 1)

If error occurs, evaluating check bits yields a binary number (e.g. 101 = 5) which indicates the exact error bit position!
