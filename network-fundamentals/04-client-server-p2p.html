Section 4.1

Introduction to Network Architecture

A network architecture defines how roles are distributed among computers in a network — specifically, which machines provide services and which consume them. The two primary models are:

  • Client-Server Model: A centralised architecture where dedicated servers provide services to client machines.
  • Peer-to-Peer (P2P) Model: A decentralised architecture where every node can act as both client and server simultaneously.

The choice of architecture profoundly impacts the network's scalability, performance, security, cost, and reliability.

Section 4.2

Client-Server Architecture

In the Client-Server model, roles are clearly divided: servers are powerful, dedicated computers that host resources and services; clients are end-user devices that request and consume those services. The server waits for requests; the client initiates communication.

Key Concepts

  • Server: A computer (or software) that provides services — file storage, database queries, web pages, email. It runs continuously, waiting for client requests.
  • Client: A device (PC, phone, browser) that sends requests to a server and processes the response.
  • Request-Response Protocol: The fundamental interaction pattern — client sends a request; server processes and returns a response.
  • Dedicated Roles: Servers are optimised for serving; clients are optimised for user interaction.

Types of Client-Server Models

  • 1-Tier Architecture: All components (presentation, business logic, data) on one machine. E.g., standalone desktop app with local DB.
  • 2-Tier Architecture: Client directly communicates with the database server. E.g., desktop app connecting directly to a remote DB server.
  • 3-Tier Architecture: Three layers — Presentation (client/browser), Application (web server/API), Data (database server). Most common in modern web apps.
  • N-Tier Architecture: Extension of 3-tier with additional layers (e.g., caching server, message queue, microservices).

Examples of Client-Server

  • Web Browsing: Your browser (client) requests HTML from a web server (Apache, Nginx). HTTP protocol.
  • Email: Email client (Outlook) downloads mail from a mail server (SMTP/IMAP).
  • FTP: FTP client transfers files to/from an FTP server.
  • Online Banking: Browser → Bank's web server → Core banking database server.
  • DNS: Your device (client) queries a DNS server for IP address resolution.
  • DHCP: A new device (client) requests an IP address from a DHCP server.

Advantages

  • Centralised data management and backup
  • Strong security — access control at server level
  • Easy to update/upgrade — only server needs updating
  • Dedicated server resources → better performance
  • Easier to monitor and administer
  • Suitable for large, complex applications

Disadvantages

  • Server = single point of failure
  • Expensive dedicated server hardware required
  • Requires skilled network/server administration
  • Server congestion under heavy load
  • Network dependent — offline access limited

Section 4.3

Peer-to-Peer (P2P) Architecture

In a Peer-to-Peer (P2P) network, all nodes (peers) are equal and have the same capabilities. Every node can simultaneously act as both a client (requesting services) and a server (providing services). There is no central dedicated server.

Each peer shares a portion of its resources (processing power, bandwidth, storage, files) directly with other peers without going through a central server.

Types of P2P Networks

  • Pure P2P (Decentralised): No central server at all. Every peer is equal. E.g., early Gnutella network. Difficult to search/discover peers.
  • Hybrid P2P (Semi-centralised): A central server (tracker) helps peers find each other, but actual data transfer is peer-to-peer. E.g., BitTorrent with trackers.
  • Structured P2P: Uses Distributed Hash Tables (DHT) to organize peers. E.g., Kademlia used in BitTorrent DHT, Chord protocol.

How BitTorrent Works (Example)

  • A torrent file contains metadata about the file and a list of trackers.
  • The tracker server maintains a list of all peers sharing that torrent (seeders and leechers).
  • Your client contacts the tracker, gets a list of peers, and starts downloading pieces from multiple peers simultaneously.
  • As you download, you also upload pieces to other peers — you are simultaneously a client and server.
  • The more peers (seeders), the faster the download — unlike client-server where one server serves all.

Examples of P2P Networks

  • BitTorrent: File sharing — movies, software, legal distributions (Linux ISOs).
  • Blockchain / Bitcoin: Distributed ledger where each node stores the complete blockchain. No central bank.
  • Skype (original): Used P2P for voice/video calls between peers.
  • Windows File Sharing: Simple home/office file sharing between workstations without a dedicated server.
  • IPFS (InterPlanetary File System): P2P distributed file system for the decentralised web.

Advantages

  • No central point of failure
  • Scales well — more peers = more capacity
  • No dedicated server hardware needed
  • Low setup cost
  • Resources grow with the network
  • Resilient to censorship

Disadvantages

  • Difficult to manage and secure
  • No centralised access control
  • Performance varies by peer availability
  • Data integrity hard to guarantee
  • Often used for illegal file sharing
  • Search/discovery is complex

Section 4.5

Hybrid Architecture

Many modern systems use a hybrid architecture that combines elements of both client-server and P2P models to get the best of both worlds.

Example: BitTorrent
Hybrid BitTorrent
Uses a central tracker server to register peers (client-server) but actual file transfer happens directly between peers (P2P).
Example: Napster
Napster (Original)
Central server maintained the music index; actual MP3 files were transferred between peers. Centralised discovery, decentralised delivery.
Example: WhatsApp
Modern Messaging Apps
Messages routed through WhatsApp servers (C-S), but media sometimes uses direct transfer. End-to-end encryption treats keys as P2P.
Example: CDN
Content Delivery Networks
Netflix uses a centralised server for auth/metadata but distributes content to edge servers (mini-servers near users) for fast delivery.

Section 4.6

When to Use Which?

Use Client-Server When:

  • You need centralised data management — HR systems, accounting, databases.
  • Strong security and access control is required — banking, healthcare, military.
  • You need consistency of data — all users must see the same current data.
  • The organisation has IT staff to manage dedicated servers.
  • You have a large number of users who need simultaneous access to the same resources.

Use Peer-to-Peer When:

  • Small network (home, small office) with limited budget — no need for a dedicated server.
  • You need a fault-tolerant, resilient system with no single point of failure.
  • You need to distribute large amounts of content efficiently (BitTorrent).
  • You want a decentralised, censorship-resistant system (blockchain).
  • Each node has resources to share and the network grows with participants.

Exam Tip
Key difference in one line:
Client-Server = "One server, many clients. Server is boss."
P2P = "All equal. Everyone is both client and server."

For exams: Client-server is for enterprise/security; P2P is for file sharing/blockchain.
