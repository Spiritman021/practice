21.1 TCP Flow Control (Sliding Window & rwnd)

Flow Control prevents a fast sender from overwhelming a slow receiver's buffer. TCP uses a **Dynamic Sliding Window Protocol**.

The receiver continuously advertises its available buffer space via the **Receiver Window (rwnd)** field in TCP header ACK updates.

🧮
Receiver Window Formula
rwnd = Receiver Buffer Size - (Last Byte Received - Last Byte Read by Application)
Sender must ensure: (Last Byte Sent - Last Byte Acked) ≤ rwnd
⚠️
Section 21.2

Silly Window Syndrome & Solutions

Silly Window Syndrome (SWS) occurs when data is transmitted in tiny 1-byte chunks, causing 40 bytes of TCP/IP header overhead for 1 byte of payload!

Sender Solution
Nagle's Algorithm
Sender buffers small outgoing data chunks until a full-sized segment (MSS) is formed or an ACK for previous segment arrives.
Receiver Solution
Clark's Solution
Receiver avoids advertising tiny window updates (advertises rwnd = 0 until buffer space ≥ MSS or half of total buffer).
🚦
Section 21.3

TCP Congestion Control Overview

While flow control protects the receiver, Congestion Control protects the intermediate network routers from buffer overflow.

📐
Effective Transmission Window Formula
Effective Window = min(cwnd, rwnd)
where cwnd is the Congestion Window (managed by sender) and rwnd is Receiver Window (advertised by receiver).

21.4 Slow Start & Congestion Avoidance (AIMD)

1. Slow Start Phase (Exponential Growth)

  • Initial cwnd starts at 1 MSS (Maximum Segment Size).
  • For every received ACK, cwnd increases by 1 MSS (doubles every RTT: 1 → 2 → 4 → 8 → 16 MSS).
  • Continues until cwnd reaches the **Slow Start Threshold (ssthresh)**.

2. Congestion Avoidance Phase (AIMD - Linear Growth)

  • When cwnd ≥ ssthresh, growth shifts to **Additive Increase**.
  • cwnd increases by 1 MSS per RTT (linear growth: 16 → 17 → 18 → 19 MSS).
  • Upon packet loss / timeout (**Multiplicative Decrease**):
    Set ssthresh = cwnd / 2, and reset cwnd = 1 MSS.

21.5 Fast Retransmit & Fast Recovery

1. Fast Retransmit

If a single segment is lost in a stream, the receiver sends **3 duplicate ACKs** for the missing segment. Upon receiving 3 duplicate ACKs, the sender immediately retransmits the missing segment **WITHOUT waiting for the Retransmission Timeout (RTO) timer** to expire!

2. Fast Recovery

Instead of resetting cwnd back to 1 MSS after 3 duplicate ACKs, TCP skips Slow Start and goes directly into Congestion Avoidance with cwnd = ssthresh + 3 MSS.
