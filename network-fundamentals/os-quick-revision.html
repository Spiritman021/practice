Operating System Basics & Kernel Architectures TOP PRIORITY 🔥
Definition, functions, types, monolithic vs microkernel, preemptive kernel
Operating System (OS): System software that acts as an intermediary / interface between the user/applications and computer hardware.
Main Functions of OS
  • Process Management: CPU allocation, scheduling, process creation/termination.
  • Memory Management: Allocation/deallocation of primary RAM, paging, virtual memory.
  • File & I/O Management: File system abstraction, device driver coordination, disk scheduling.
  • Protection & Security: Authentication, authorization, access control matrix.
Types of Operating Systems
OS TypeKey Idea & Behavior
Batch OSJobs with similar needs grouped into batches and processed without user interaction.
Multiprogramming OSKeeps multiple jobs in memory simultaneously so CPU always has a job to execute (maximizes CPU utilization).
Multitasking / Time-SharingCPU switches between tasks so rapidly that users can interact with each program running.
Multiprocessing OSUses multiple physical CPUs/cores to execute processes in true hardware parallelism.
Distributed OS vs Network OS ⭐Distributed: Multiple independent machines appear as a single unified system (transparent).
Network: Machines remain autonomous; OS provides services to access remote shared files/printers.
Real-Time OS (RTOS)Strict, guaranteed response time limits (Hard RTOS vs Soft RTOS).
Kernel Architectures 🔥
ArchitectureHow It WorksPros & Cons / Examples
Monolithic KernelAll OS services (file system, VFS, device drivers, IPC, memory mgmt) run inside kernel space as one single binary image.Very Fast, but a single driver crash can crash the entire OS. (Linux, traditional Unix).
MicrokernelOnly bare essentials (IPC, minimal scheduling, basic virtual memory) stay in kernel space; drivers and file systems run as user-space services.Highly secure & modular, but message-passing IPC adds performance overhead. (Minix, QNX).
Hybrid KernelCombines monolithic speed with microkernel modularity.Used in modern Windows NT, macOS (XNU kernel).
ExokernelAllocates raw hardware directly to apps with minimal abstraction.Customized application-level OS libraries.
🧠 Preemptive vs Non-Preemptive Kernel
Preemptive Kernel: A process running in kernel mode can be preempted by a higher priority process.
Non-Preemptive Kernel: A process in kernel mode runs uninterrupted until it exits kernel mode or blocks.

System Calls & Dual-Mode Operation
User Mode ↔ Kernel Mode, Categories, fork(), exec(), exit(), wait()
System Call: Programmatic interface through which a user program requests privileged services from the OS kernel. Causes a software interrupt / trap that switches CPU from User Mode (Mode bit = 1) to Kernel Mode (Mode bit = 0).
Major System Call Categories
CategoryKey System CallsFunction
Process Controlfork(), exec(), exit(), wait()Create child process, load executable, terminate, wait for child.
File Managementopen(), read(), write(), close(), unlink()File manipulation operations.
Device Managementioctl(), read(), write()Request and release device resources.
Information Maintenancegetpid(), alarm(), time()Get system/process timing and metadata.
Communication / IPCpipe(), shmget(), socket()Inter-process message/shared memory communication.
🔑 System Call vs API vs System Program
API (e.g. C printf, malloc): Programming library functions.
System Call (e.g. write(), sbrk()): The actual trap into kernel mode invoked under the hood.
System Program (e.g. ls, ps, bash): User-space utilities built on top of system calls.

Processes, Process States & PCB TOP PRIORITY 🔥🔥
5-State Model, PCB, Context Switch, Schedulers, Zombie & Orphan
Program (Passive)

Passive entity stored on disk (executable file, e.g. a.out).

Process (Active) ⭐

Program in execution. Includes program counter, stack, data, heap, and registers.

5-State Process Lifecycle Model
New→ Ready↔ Running→ Terminated

Running→ Waiting / Blocked (I/O event)→ Ready (I/O complete)
PCB — Process Control Block Contents
  • PID (Process ID), Process State (Ready/Running/Waiting).
  • Program Counter (PC): Address of next instruction to execute.
  • CPU Registers: Accumulators, index registers, stack pointers.
  • CPU Scheduling info: Priority, scheduling queue pointers.
  • Memory Management info: Base/limit registers or Page tables.
  • I/O Status & Accounting info: Open files list, allocated I/O devices.
Types of Schedulers 🔥
SchedulerAlternative NamePrimary FunctionExecution Frequency
Long-Term SchedulerJob SchedulerSelects processes from job pool on disk into RAM ready queue. Controls Degree of Multiprogramming.Infrequent (Seconds/Minutes)
Short-Term SchedulerCPU SchedulerSelects which ready process in RAM gets the CPU next.Very frequent (Milliseconds)
Medium-Term SchedulerSwapperHandles swapping (moves blocked/idle processes to disk swap space to free RAM).Intermediate frequency
Zombie Process ⭐

Process has terminated, but its entry remains in process table because parent hasn't yet read its exit status via wait().

Orphan Process ⭐

Parent process terminates before its child. The orphan process is automatically adopted by the init process (PID = 1).

🔑 Context Switching & Dispatcher
Context Switch: Saving state of old process into its PCB and loading state of new process from its PCB. Pure computational overhead (CPU does zero productive work during switch).
Dispatcher: The OS module that gives control of CPU to the process selected by short-term scheduler.
4
CPU Scheduling Algorithms & Formulas TOP PRIORITY 🔥🔥
TAT, WT, RT Formulas & FCFS, SJF, SRTF, Priority, RR, Multilevel Queue
Golden CPU Scheduling Formulas 🔥
Turnaround Time (TAT) = Completion Time (CT) − Arrival Time (AT) Waiting Time (WT) = Turnaround Time (TAT) − Burst Time (BT) Response Time (RT) = First CPU Allocation Time − Arrival Time (AT)
AlgorithmPreemptive?Key Characteristic & Evaluation
FCFS (First Come First Serve)NoSimple. Suffers from Convoy Effect (short processes wait behind long CPU-bound process).
SJF (Shortest Job First)NoSelects process with shortest burst time. Gives provably minimum average waiting time. Difficult to know future burst time.
SRTF (Shortest Remaining Time First)YesPreemptive version of SJF. Process with smallest remaining time preempts current running process.
Priority SchedulingEitherCPU allocated to highest priority. Suffers from Starvation. Solved by Aging (gradually boosting priority of waiting jobs).
Round Robin (RR) ⭐YesTime-shared execution with fixed Time Quantum (q). Fair response times. If q → ∞, behaves like FCFS; if q → 0, excessive context switch overhead.
Multilevel QueueEitherReady queue partitioned into fixed separate queues (e.g. Foreground interactive vs Background batch). Fixed priority among queues.
Multilevel Feedback Queue (MLFQ) ⭐EitherProcesses can dynamically move between queues based on CPU-burst history and aging. Most general and flexible CPU scheduler.

Threads & Multithreading Models HIGH YIELD
Lightweight process, User vs Kernel threads, Many-to-One, One-to-One, Many-to-Many
Thread: Smallest unit of CPU execution ("lightweight process"). A process can contain multiple threads of execution.
Shared by All Threads in Process

• Code segment
• Data segment (global variables)
• OS resources (open files & signals)
• Heap memory

Private to Each Individual Thread

• Thread ID (TID)
• Program Counter (PC)
• Register set
• Stack (local variables & function calls)

Multithreading Models
ModelMappingPros & Cons
Many-to-OneMany User threads → 1 Kernel threadFast thread management in user space, but if one thread makes a blocking system call, the entire process blocks. Cannot run in parallel on multi-core.
One-to-One ⭐1 User thread → 1 Kernel threadTrue concurrency and parallel execution on multi-core. Overhead of creating kernel threads (used in Linux & Windows).
Many-to-ManyMany User threads → Fewer/Equal Kernel threadsFlexible multiplexing; avoids bottleneck of many-to-one and overhead of one-to-one.
6
Inter-Process Communication (IPC)
Shared Memory, Message Passing, Pipes, Sockets, RPC
Shared Memory (Fastest)

Processes share a common memory region mapped to their address spaces. Extremely fast (zero kernel copy overhead), but requires application-level synchronization.

Message Passing

Processes exchange messages via kernel system calls (send(), receive()). Useful in distributed systems; avoids shared-memory conflict.

Other IPC Mechanisms
  • Ordinary Pipes: Unidirectional producer-consumer byte stream between parent and child processes.
  • Named Pipes (FIFOs): Bidirectional, persistent in file system, accessible by unrelated processes.
  • Sockets: Network endpoint communication across machines (IP + Port).
  • RPC (Remote Procedure Call): Abstracts procedure calls across network as if executing locally.

Process Synchronization & Race Condition TOP PRIORITY 🔥
Concurrent access anomalies on shared resources
Race Condition: A situation where multiple concurrent processes access and manipulate shared data, and the final outcome depends on the specific order in which instructions execute.
Race Condition Example (Shared Counter = 10): Thread A reads counter = 10 | Thread B reads counter = 10 Thread A increments → 11 | Thread B increments → 11 Thread A writes → 11 | Thread B writes → 11 Expected Counter = 12, Actual Counter = 11 (Data Corrupted!)
8
The Critical Section Problem & 3 Requirements ⭐⭐⭐
Mutual Exclusion, Progress, Bounded Waiting
Critical Section (CS): Piece of code where shared resources (variables, files, tables) are accessed and modified.
RequirementMandatory Rule
1. Mutual Exclusion ⭐If process Pi is executing in its critical section, no other process can be executing in their critical section.
2. Progress ⭐If no process is in CS and some processes wish to enter, only those processes not in their remainder section can participate in deciding who enters next, and selection cannot be postponed indefinitely.
3. Bounded Waiting ⭐There must be a bound on the number of times other processes are allowed to enter CS after a process has made a request to enter (prevents indefinite starvation).
9
Synchronization Mechanisms
Mutex, Semaphore, Monitors, Test-and-Set, Spinlocks
Mutex (Mutual Exclusion Lock)

Binary locking mechanism with strict ownership (only the thread that locked the mutex can unlock it).

Semaphore (Dijkstra) ⭐

Integer synchronization variable accessed via two atomic operations: wait() / P() (decrements) and signal() / V() (increments).

Semaphore TypeValue RangeUse Case
Binary Semaphore0 or 1Mutual exclusion (similar to Mutex, but no ownership concept).
Counting Semaphore0 to N (Unrestricted integer)Resource allocation from a pool of N identical available resource instances.
  • Monitor: High-level language synchronization construct containing shared data variables, condition variables (wait/signal), and procedures. Only one process can be active inside a monitor at a time.
  • Hardware Atomic Instructions: TestAndSet() and CompareAndSwap() execute without interruption at hardware level.
  • Spinlock: A lock where waiting processes loop/poll continuously (busy waiting). Efficient for very short wait times on multiprocessors.
10
Classic Synchronization Problems
Producer-Consumer, Readers-Writers, Dining Philosophers
ProblemDescription & Semaphore Setup
Producer–Consumer (Bounded Buffer)Producer puts items into buffer; Consumer removes items. Uses 3 semaphores: mutex (mutual exclusion = 1), empty (N), full (0).
Readers–WritersMultiple readers can read concurrently; Writers require exclusive access. Uses rw_mutex and read_count.
Dining Philosophers5 philosophers share 5 chopsticks (need 2 chopsticks to eat). Demonstrates resource contention and deadlock avoidance.
11
Peterson's Algorithm
Classic software mutual exclusion solution for 2 processes
Peterson's Algorithm is a classic software solution for two processes (P0, P1) that satisfies Mutual Exclusion, Progress, and Bounded Waiting. Uses two shared variables: boolean flag[2] and int turn.
12
Lamport's Bakery Algorithm
Mutual exclusion for N processes (Token ticket system)
Bakery Algorithm (Leslie Lamport): Provides mutual exclusion for N processes. Each process receives a ticket number upon entering; the process with the lowest ticket number gets to enter the critical section next.
13
Deadlocks & Deadlock vs Livelock TOP PRIORITY 🔥🔥
Definition, circular dependencies & state comparisons
Deadlock: A set of processes are blocked because each process is holding a resource and waiting for another resource acquired by some other process in the set.
Deadlock (Blocked)

Processes are permanently blocked/sleeping in waiting state; zero CPU usage and zero state changes occur.

Livelock (Active Loop)

Processes actively change state in response to each other, but make zero forward progress (e.g. two people in a hallway repeatedly stepping to the same side).

14
Four Necessary Conditions for Deadlock ⭐⭐⭐
M-H-N-C (Coffman Conditions)
ConditionMeaningPrevention Strategy
1. Mutual ExclusionAt least one non-sharable resource held exclusively.Make resources sharable (e.g. read-only files, spooling).
2. Hold and WaitProcess holds ≥1 resource while requesting others.Process must request all resources at start, or release held resources before requesting.
3. No PreemptionResources cannot be forcibly taken from a process.Preempt held resources if a new request cannot be allocated immediately.
4. Circular WaitA closed chain of processes exists: P0 → P1 → ... → Pn → P0.Impose total global ordering on all resource types and require ascending allocation.
🧠 Mnemonic & Rule
M-H-N-C (Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait). Breaking ANY ONE condition guarantees deadlock cannot occur.
15
Deadlock Handling & Resource Allocation Graph (RAG)
Prevention, Avoidance, Detection, Recovery & RAG Cycle Rules
StrategyApproach
Deadlock PreventionDesign system protocols to invalidate at least one of the 4 Coffman conditions.
Deadlock AvoidanceOS checks every resource request dynamically using Banker's Algorithm to ensure system stays in a Safe State.
Deadlock Detection & RecoveryAllow deadlocks to occur; periodically run detection algorithm (Wait-for Graph / RAG), then recover via process termination or preemption.
Ostrich Algorithm (Ignore)Ignore the problem completely (used in Unix/Linux/Windows where deadlocks are rare).
Resource Allocation Graph (RAG) Cycle Rules 🔥
  • If graph has NO cycle → Guaranteed NO deadlock ✓
  • If graph HAS a cycle and each resource has ONLY ONE instance → Definitely DEADLOCK ✘
  • If graph HAS a cycle with MULTIPLE resource instances → MAY OR MAY NOT be deadlock.
16
Safe State vs Unsafe State
Safe sequence existence & deadlock relationship
Safe State: There exists at least one safe execution sequence such that every process can satisfy its maximum resource needs and complete without deadlock.
⚠ Important Distinction
Safe State is a subset of No Deadlock.
Unsafe State ≠ Deadlock (An unsafe state merely creates the possibility of a deadlock).
17
Banker's Algorithm (Deadlock Avoidance) ⭐⭐⭐
Available, Max, Allocation, Need Matrix & Safety Algorithm
🔑 Core Formula
Need Matrix [i, j] = Max[i, j] − Allocation[i, j]
Safety Algorithm: 1. Work = Available, Finish[i] = false for all i. 2. Find index i such that: Finish[i] == false AND Need[i] ≤ Work. 3. Work = Work + Allocation[i], Finish[i] = true, repeat step 2. 4. If Finish[i] == true for ALL processes → System is in a SAFE STATE!

Memory Management Basics & MMU
Logical / Virtual Address vs Physical Address, Memory Management Unit
Logical / Virtual Address

Generated by the CPU during program execution (address space visible to program).

Physical Address

Actual hardware address loaded onto the memory bus to access physical RAM chips.

MMU (Memory Management Unit): Hardware device that converts CPU logical addresses into physical memory addresses at runtime (using base/relocation registers or page tables).

Internal vs External Fragmentation & Compaction ⭐⭐
Definitions, causes and compaction solution
Internal Fragmentation

Unused allocated space inside a partition/page block (e.g. process requests 18KB inside a 20KB page → 2KB wasted internally).

External Fragmentation

Total free memory is enough to satisfy a request, but it is scattered non-contiguously in small disjoint holes.

🔑 Compaction
Technique to resolve external fragmentation by shifting all allocated processes to one end of memory to combine free holes into one large contiguous block. Requires dynamic address binding at execution time.
21
Dynamic Memory Allocation Algorithms & Buddy System
First Fit, Best Fit, Worst Fit, Next Fit, Buddy System
AlgorithmMechanismPerformance / Note
First FitAllocate the first free block that is large enough.Fastest search time; memory efficient.
Best FitAllocate the smallest free block that is large enough.Slow (searches entire list); produces tiny unusable leftover holes.
Worst FitAllocate the largest available free block.Leaves largest leftover hole, but generally worst performance.
Buddy System ⭐Memory divided into power-of-2 blocks. Splits blocks recursively and merges adjacent free "buddies" on free.Fast allocation and merging, but causes internal fragmentation.
22
Paging TOP PRIORITY 🔥🔥
Pages, Frames, Page Table & Address Translation
Paging: Non-contiguous memory allocation scheme. Physical memory is divided into fixed-size blocks called Frames; Logical memory is divided into same-sized blocks called Pages. (Page size = Frame size).
Logical Address = [ Page Number (p) | Offset (d) ] Physical Address = [ Frame Number (f) | Offset (d) ] Page Table maps: Page Number (p) → Frame Number (f)
⭐ Key Exam Advantage
Paging completely eliminates External Fragmentation (though slight Internal Fragmentation may exist in the last page of a process).
23
Page Table Structures
Hierarchical / Multi-Level, Hashed, Inverted Page Table
Page Table StructureHow It Works & Exam Point
Hierarchical / Multi-levelPage table itself is paged into multiple levels (e.g. Two-level paging) to avoid keeping massive contiguous page tables in RAM.
Hashed Page TableUses a hash table where hash value points to a linked list of page entries; common in address spaces > 32 bits.
Inverted Page Table ⭐Has one entry per physical frame in RAM rather than per logical page. Dramatically saves memory, but requires search/hash per reference.
24
TLB (Translation Lookaside Buffer) & EMAT ⭐⭐⭐
Hardware cache for page tables & Effective Memory Access Time formula
TLB: High-speed associative hardware cache inside CPU that stores recently used Page Number → Frame Number translations.
🔑 Effective Memory Access Time (EMAT) Formula
Let h = TLB hit ratio, c = TLB search time, m = Main memory access time:
EMAT = h × (c + m) + (1 − h) × (c + 2m)
(On TLB hit: access TLB + 1 memory access for data; On TLB miss: access TLB + 1 memory access for page table + 1 memory access for data).

26
Virtual Memory Concepts
Execution of processes larger than physical RAM
Virtual Memory: Separation of user logical memory from physical memory. Allows execution of programs that are larger than physical RAM by swapping pages between RAM and secondary backing store.
27
Demand Paging, Page Fault & Copy-on-Write (COW) ⭐⭐
Lazy swapper, Page fault handling steps, COW optimization
Demand Paging: Pages are loaded into RAM only when accessed / referenced by CPU during execution (Lazy Swapper).
Page Fault Handling Sequence
1. CPU generates address→ 2. Invalid bit in Page Table→ 3. Trap (Page Fault)→ 4. Fetch page from disk→ 5. Write to free Frame→ 6. Update Page Table & Restart instruction
🔑 Copy-on-Write (COW)
When a process forks a child, parent and child initially share the same physical pages (marked read-only). A private copy of a page is created only when either process writes to it, saving memory and time.

Page Replacement Algorithms TOP PRIORITY 🔥🔥
FIFO, Optimal (OPT / MIN), LRU, LFU, MFU, Second Chance
AlgorithmReplacement StrategyKey Exam Facts
FIFO (First-In, First-Out)Replaces the oldest page loaded into memory.Simple, but suffers from Belady's Anomaly.
Optimal (OPT / MIN / Belady's)Replaces page that will not be used for the longest period in the future.Produces theoretical minimum page faults. Impossible to implement in practice (requires future knowledge). Used as benchmark.
LRU (Least Recently Used) ⭐Replaces page that has not been used for the longest time in the past.Approximates Optimal. Free from Belady's Anomaly. Implemented with counters or stack.
LFU / MFULFU: Replaces page with smallest reference count.
MFU: Replaces page with highest reference count.		Counting-based algorithms; higher implementation overhead.
Second Chance / ClockFIFO + Reference bit check. If bit=1, reset bit to 0 and give second chance; replace first page with bit=0.Circular queue clock pointer implementation.
29
Belady's Anomaly ⭐⭐⭐
More frames causing more page faults (FIFO phenomenon)
Belady's Anomaly: The counter-intuitive phenomenon where allocating more physical page frames results in an INCREASE in the number of page faults for certain memory reference strings.
Primarily observed in: FIFO algorithm.
(Stack-based algorithms like LRU and Optimal NEVER suffer from Belady's Anomaly).
30
Thrashing TOP PRIORITY 🔥
High paging activity, low CPU utilization, working set solution
Thrashing: State where the system spends more time servicing page faults and swapping pages in/out than executing productive application instructions.
Key Indicators: Extremely high page fault rate + Disk I/O saturation + Drastic drop in CPU utilization.
🧠 Solutions to Thrashing
1. Reduce Degree of Multiprogramming (suspend/swap out some processes).
2. Allocate more physical page frames to active processes.
3. Use the Working-Set Model or Page-Fault Frequency (PFF) strategy.
31
Working Set Model (Peter Denning)
Working set window Δ and thrashing prevention
Working Set (W(t, Δ)): Set of pages referenced by a process in the most recent Δ page reference window. If total memory demand exceeds total RAM frames, OS suspends a process to prevent thrashing.

34
File Access Methods
Sequential Access, Direct / Random Access, Indexed Access
Sequential Access

Bytes/records read in order from beginning to end (e.g. magnetic tape, audio files).

Direct / Random Access

Reads/writes arbitrary block immediately using relative block number (e.g. database disk blocks).

Indexed Access

Uses an index table of keys to locate specific records quickly.

35
Directory Structures
Single-Level, Two-Level, Tree, Acyclic Graph, General Graph
  • Single-Level: Single directory for all files (naming collisions).
  • Two-Level: Separate User File Directory (UFD) per user under Master File Directory (MFD).
  • Tree-Structured ⭐: Hierarchical tree with root, subdirectories, and files (standard in Windows/Unix).
  • Acyclic Graph: Allows shared subdirectories/files via links without permitting cycles.
  • General Graph: Allows arbitrary links; requires cycle detection for garbage collection.
36
File Allocation Methods HIGH YIELD
Contiguous, Linked (FAT), Indexed Allocation
Allocation MethodHow It WorksPros & Cons
Contiguous AllocationFile occupies a set of consecutive contiguous disk blocks.Fastest direct access, but suffers from External Fragmentation and file growth limitations.
Linked Allocation (FAT)Each disk block contains a pointer to the next block.No external fragmentation, but slow sequential traversal (no direct access) and pointer overhead.
Indexed Allocation ⭐An Index Block stores an array of pointers to all allocated data blocks.Excellent direct access without external fragmentation; overhead of index blocks for small files.
37
Free Space Management
Bit Vector (Bitmap), Linked Free List, Grouping, Counting
  • Bit Vector / Bitmap: 1 bit per disk block (0 = allocated, 1 = free). Simple and fast hardware-supported search.
  • Linked Free List: Free blocks linked together via pointers.
  • Grouping: Stores addresses of N free blocks in first free block.
  • Counting: Stores address of first free contiguous block and length of run.
38
Inodes in Unix / Linux File Systems ⭐⭐
Inode structure, metadata & direct/indirect block pointers
Inode (Index Node): Data structure in Unix/Linux storing all metadata of a file (file size, permissions, owner, timestamps, block pointers).
Note: Filename is NOT stored in inode; it is stored in directory entries mapped to inode numbers.
  • Direct Pointers (typically 12 pointers pointing directly to data blocks).
  • Single Indirect Pointer (points to a block containing pointers to data blocks).
  • Double Indirect Pointer (points to a block of single indirect blocks).
  • Triple Indirect Pointer (enables support for multi-terabyte files).
39
Disk Scheduling Algorithms & RAID Levels TOP PRIORITY 🔥🔥
FCFS, SSTF, SCAN (Elevator), C-SCAN, LOOK, C-LOOK & RAID 0, 1, 5, 6
AlgorithmBehavior & Arm Movement
FCFSServices I/O requests in arrival order. No starvation, but high seek time.
SSTF (Shortest Seek Time First)Services request closest to current head position. Minimizes average seek time; may cause starvation of distant tracks.
SCAN (Elevator Algorithm) ⭐Disk arm moves in one direction to the disk boundary servicing requests, then reverses direction.
C-SCAN (Circular SCAN)Moves in one direction to the boundary servicing requests, then immediately jumps back to the beginning without servicing on return. Provides uniform wait times.
LOOKLike SCAN, but reverses at the last pending request rather than traveling all the way to the disk edge.
C-LOOK ⭐Like C-SCAN, but jumps from the last request in servicing direction directly to the first pending request at opposite end.
RAID (Redundant Array of Independent Disks) Levels
RAID LevelTechniqueFault Tolerance / Features
RAID 0Block StripingHigh performance, Zero fault tolerance (1 disk fails = all data lost).
RAID 1Mirroring (1:1 copy)Full redundancy, high read speed, 50% capacity overhead.
RAID 5 ⭐Block Striping + Distributed ParityTolerates 1 disk failure. Excellent balance of cost, performance & protection.
RAID 6Block Striping + Dual Distributed ParityTolerates 2 simultaneous disk failures.
RAID 10 (1+0)Mirrored + StripedCombines RAID 1 mirroring with RAID 0 striping.

I/O Management & Device Types
Character Devices vs Block Devices
Character Devices

Transfers unbuffered stream of bytes one character at a time (e.g. Keyboard, Mouse, Serial Ports).

Block Devices

Transfers fixed-size blocks of data with random access seeking (e.g. Hard Disks, SSDs, USB storage).

42
Interrupts & Interrupt vs Polling
Hardware vs Software Interrupts (Traps), IVT, Interrupt Handler
  • Hardware Interrupt: Signal sent via physical pin from device (e.g. keyboard stroke, timer).
  • Software Interrupt (Trap / Exception): Generated by CPU instruction (e.g. division by zero, system call).
  • Interrupt Vector Table (IVT): Table of memory addresses pointing to Interrupt Service Routines (ISRs).
🧠 Interrupt vs Polling
Interrupt = Device alerts CPU when ready  |  Polling = CPU repeatedly asks device if ready.

Protection & Security
Authentication vs Authorization & Security Threats
Authentication

"Who are you?" — Verifying user identity (Password, OTP, Biometrics).

Authorization

"What are you allowed to do?" — Determining user access rights and permissions.

Common Security Threats
  • Virus: Replicates by attaching to host files.
  • Worm: Self-replicating standalone program over network.
  • Trojan Horse: Malicious program disguised as legitimate software.
  • Buffer Overflow: Writing data beyond allocated buffer boundaries to overwrite execution return pointers.

Capability List (C-List)

Stored by row (Subject/User): User possesses a secure token/ticket listing accessible objects.

Spooling (Simultaneous Peripheral Operations On-Line): Data is temporarily staged into a buffer/queue on disk for a slower peripheral device (classic example: Print Spooler, where multiple print jobs queue up and print sequentially while CPU continues other work).

Virtualization & Hypervisors
Type 1 (Bare Metal) vs Type 2 (Hosted) Hypervisors
Type 1 Hypervisor (Bare-Metal) ⭐

Runs directly on underlying computer hardware (no host OS). Fast and enterprise-grade. Examples: VMware ESXi, Microsoft Hyper-V, KVM, Xen.

Type 2 Hypervisor (Hosted)

Runs on top of an existing host OS as an application. Examples: Oracle VirtualBox, VMware Workstation.

Key Exam Differences Summary TOP PRIORITY 🔥🔥
Process vs Thread, Mutex vs Semaphore, Deadlock vs Starvation
ComparisonOption AOption B
Process vs ThreadProcess: Heavyweight, isolated address space, expensive context switch.Thread: Lightweight, shares address space, cheap context switch.
Mutex vs SemaphoreMutex: Locking mechanism with strict ownership (lock/unlock by same thread).Semaphore: Signaling mechanism (no ownership, wait/signal integer).
Deadlock vs StarvationDeadlock: Permanent circular waiting, no process can proceed.Starvation: Indefinite delay because high-priority processes monopolize CPU (solved by Aging).
Monolithic vs MicrokernelMonolithic: All services in kernel space (Fast, but single bug crashes OS).Microkernel: Minimal services in kernel, rest in user space (Modular & stable, slower IPC).
Preemptive vs Non-PreemptivePreemptive: CPU can be taken away forcefully (RR, SRTF).Non-Preemptive: Process retains CPU until voluntary completion/yield (FCFS, SJF).
