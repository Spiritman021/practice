22.1 Session Layer (OSI Layer 5) Overview

The Session Layer is responsible for establishing, managing, synchronizing, and terminating communication sessions between applications running on different network hosts.

Key Responsibilities of Layer 5

  • Session Establishment & Maintenance: Sets up virtual sessions between application processes (e.g. database connections, video conferencing streams).
  • Dialog Control: Manages which node sends data and when (Simplex, Half-Duplex, or Full-Duplex).
  • Synchronization & Recovery: Inserts checkpoints into long data streams so that if a crash occurs, retransmission resumes from the last valid checkpoint rather than the beginning.
💬
Section 22.2

Dialog Control & Token Management

Dialog control regulates the direction of communication between applications using Software Tokens:

Dialog ModeMechanismExample Application
Simplex SessionOne-way data flow only (Sender → Receiver).Radio broadcast, Sensor telemetry.
Half-Duplex SessionTwo-way data flow, but only one side transmits at a time (uses Data Token).Walkie-talkie, Terminal login session.
Full-Duplex SessionSimultaneous two-way data transmission without tokens.VoIP phone calls, WebSockets.
🚩
Section 22.3

Synchronization & Checkpointing

For large file transfers (e.g. 1 GB document), the Session Layer inserts **Synchronization Points (Checkpoints)** into the stream:

📍
Major vs Minor Synchronization Points
• Minor Checkpoints: Inserted frequently (e.g. every 100 pages). Requires local acknowledgement; if a failure occurs, resends only from the last minor point.
• Major Checkpoints: Divides a session into independent logical units. Requires explicit confirmation before advancing.

22.4 Presentation Layer (OSI Layer 6) Overview

The Presentation Layer acts as the "translator" for the network. It formats, encodes, compresses, and encrypts data so that applications on different systems (with different character sets or hardware endianness) can understand each other.

🔤
Section 22.5

Data Translation & Syntax Encoding

  • Character Code Translation: Translates between different character encodings, such as **ASCII**, **EBCDIC**, and **Unicode (UTF-8 / UTF-16)**.
  • Data Structure Formatting: Converts complex structures into standardized Network Abstract Syntax (e.g., ASN.1 - Abstract Syntax Notation One, JSON, XML).
  • Byte Ordering (Endianness): Converts between **Big-Endian** (Network Byte Order, MSB first) and **Little-Endian** (x86 architecture host order).
🗜️
Section 22.6

Data Compression Techniques

Compression reduces the number of bits required to transmit data, conserving network bandwidth.

100% Exact Recovery
Lossless Compression
No data is lost during compression/decompression. Essential for text files, executable code, and databases. (Algorithms: GZIP, ZIP, Run-Length Encoding, Huffman Coding).
High Ratio / Minor Loss
Lossy Compression
Permanently discards non-critical perceptual detail to achieve high compression ratios. Used for multimedia (JPEG images, MP3 audio, MP4 video).
🔐
Section 22.7

Data Encryption & SSL/TLS Boundary

The Presentation Layer handles data **Encryption** at the sender and **Decryption** at the receiver to ensure confidentiality and integrity.

Encryption TypeMechanismKey UsageCommon Standard
Symmetric EncryptionSame secret key used for encryption and decryption. Fast & efficient.Single Shared Secret KeyAES-256, ChaCha20
Asymmetric EncryptionUses a public key to encrypt and a private key to decrypt. Highly secure key exchange.Public & Private Key PairRSA, ECC (Elliptic Curve)
SSL/TLS ProtocolHybrid encryption protocol operating at the Presentation/Session boundary. Uses Asymmetric for key exchange, then switches to Symmetric for bulk payload encryption.Hybrid Key ExchangeTLS 1.3
Exam Question Q100 Topic: SSL/TLS Protocol Concepts
Which of the following statements is/are correct about SSL/TLS?
I: SSL/TLS uses both symmetric and asymmetric encryption.
II: TLS is the successor of SSL.
III: SSL is more secure than TLS.
  • A. ✅ I and II ✓ Correct
  • B. I and III
  • C. II only
  • D. III only
  • E. I, II, and III
Explanation:
• Statement I is TRUE: SSL/TLS uses Asymmetric encryption (RSA/Diffie-Hellman) for key exchange & auth, and Symmetric encryption (AES) for data transmission.
• Statement II is TRUE: TLS (Transport Layer Security) was developed as the modernized successor to SSL.
• Statement III is FALSE: SSL (v2/v3) is deprecated and insecure. TLS 1.3 is significantly more secure than SSL.
