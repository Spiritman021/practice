2. Software Development Life Cycle (SDLC) Models 🔥 HIGH YIELD FULL NOTES READY
  • 2.1 Waterfall Model: Classic linear-sequential model, strict phases, frozen requirements, heavy documentation.
  • 2.2 Prototyping Model: Working prototype for early feedback, requirements elicitation, evolutionary vs throwaway prototypes.
  • 2.3 Spiral Model: Risk-driven model, 4 quadrants (Planning, Risk Analysis, Engineering, Evaluation), suitable for large complex systems.
  • 2.4 Iterative / Incremental Model: Phased release of product increments, partial implementation.
  • 2.5 V-Model (Verification & Validation): Execution of testing phases parallel to corresponding development phases.
  • 2.6 RAD Model (Rapid Application Development): Component-based, rapid development timeline (60–90 days).
  • 2.7 Agile Model:
    • 2.7.1 Agile Manifesto: 4 core values & 12 principles.
    • 2.7.2 Scrum Framework: Sprints (1–4 weeks), roles (Product Owner, Scrum Master, Dev Team), artifacts (Backlog), ceremonies (Daily Standup, Sprint Review/Retrospective).
    • 2.7.3 Extreme Programming (XP): Pair programming, TDD, continuous integration, refactoring.
    • 2.7.4 Kanban: Visual workflow board, Work-In-Progress (WIP) limits.
  • 2.8 Comparison of SDLC Models: Selection matrix based on requirement stability, project size, risk, and user involvement.

3. Software Requirement Analysis ✨ FULL NOTES READY
  • 3.1 Requirement Engineering Process: Elicitation (interviews, JAD), Analysis, Specification (SRS), Validation.
  • 3.2 Types of Requirements:
    • 3.2.1 Functional Requirements: System behavior, services, functions ($I/O$ mappings).
    • 3.2.2 Non-Functional Requirements: Quality attributes (Performance, Security, Usability, Availability, Reliability).
  • 3.3 Software Requirement Specification (SRS):
    • 3.3.1 SRS Format / Structure: IEEE 830 standard layout.
    • 3.3.2 Characteristics of Good SRS: Correct, Unambiguous, Complete, Consistent, Verifiable, Modifiable, Traceable.
  • 3.4 Feasibility Study: Technical, Economic (Cost-Benefit Analysis), Operational, Legal, Schedule feasibility.
  • 3.5 Requirement Analysis Tools:
    • 3.5.1 Data Flow Diagram (DFD): Symbols (Process, Data Store, Data Flow, External Entity), Levels (Context/Level-0, Level-1, Level-2).
    • 3.5.2 Data Dictionary: Repository of data elements, structures, and data flows.
    • 3.5.3 Entity-Relationship Diagram (ERD): Entities, Attributes, Relationships & Cardinality.
    • 3.5.4 Decision Table / Decision Tree: Rule-based logic modeling for complex conditional requirements.

4. Software Design, Coupling & Cohesion 🔥 HIGH YIELD
  • 4.1 Design Concepts & Principles: Abstraction, Modularity, Architecture, Refinement, Information Hiding.
  • 4.2 Function-Oriented Design: Structured Design, Structure Charts (Transform vs Transaction Analysis, Fan-in & Fan-out).
  • 4.3 Object-Oriented Design (OOD Basics): Classes, Objects, Abstraction, Encapsulation, Inheritance, Polymorphism.
  • 4.4 Coupling & Cohesion (Ranking 🔥):
    • 4.4.1 Types of Coupling (Worst → Best): Content > Common > Control > Stamp > Data (Strongest/Highest → Weakest/Lowest Coupling desired).
    • 4.4.2 Types of Cohesion (Worst → Best): Coincidental < Logical < Temporal < Procedural < Communicational < Sequential < Functional (Weakest/Worst → Strongest/Best Cohesion desired).
  • 4.5 Modularity & Abstraction: High Cohesion + Low Coupling principle.
  • 4.6 User Interface (UI) Design Basics: Golden rules (Place user in control, reduce memory load, maintain consistency).
  • 4.7 Software Architecture Types: Layered architecture, Client-Server, MVC (Model-View-Controller) pattern.

5. Software Project Management & Estimation Math 🔥 HIGH YIELD
  • 5.1 Project Planning: Scope, WBS (Work Breakdown Structure), Milestone definitions.
  • 5.2 Project Scheduling: Gantt Charts, PERT / CPM (Critical Path Method, Early Start, Late Start, Float/Slack time calculation).
  • 5.3 Software Cost Estimation 🔥:
    • 5.3.1 COCOMO Model 🔥: Basic, Intermediate, Detailed models. Modes: Organic ($a_b=2.4, b_b=1.05$), Semi-detached ($a_b=3.0, b_b=1.12$), Embedded ($a_b=3.6, b_b=1.20$). Formulas: $\text{Effort } E = a_b(\text{KLOC})^{b_b}$, $\text{Duration } D = c_b(E)^{d_b}$.
    • 5.3.2 Putnam Resource Allocation Model: Software equation linking size, effort, and schedule time.
    • 5.3.3 Function Point (FP) Analysis: Unadjusted FP ($\text{UFP}$) based on 5 components (Inputs, Outputs, Inquiries, Files, Interfaces) $\times \text{VAF}$.
  • 5.4 Software Size Metrics 🔥:
    • 5.4.1 Lines of Code (LOC / KLOC): Productivity & cost per LOC.
    • 5.4.2 Halstead's Software Metrics: Operators ($n_1, N_1$), Operands ($n_2, N_2$), Vocabulary $n = n_1 + n_2$, Length $N = N_1 + N_2$, Volume $V = N \log_2 n$.
    • 5.4.3 Cyclomatic Complexity 🔥: McCabe's Metric formulas: $V(G) = E - N + 2P$, $V(G) = P + 1$ (Predicates + 1), $V(G) = \text{Number of Regions}$.
  • 5.5 Risk Management: Risk Identification, Risk Projection, RMMM Plan (Mitigation, Monitoring, Management).
  • 5.6 Personnel Planning: Team structures (Democratic, Chief Programmer, Controlled Centralized).
  • 5.7 Software Configuration Management (SCM): Baselines, Version Control, Change Control Board (CCB), Audits.

6. Software Quality & CMM Maturity Levels 🔥 HIGH YIELD
  • 6.1 Software Quality Assurance (SQA): SQA activities vs Quality Control (QC), Quality audits, Verification vs Validation in quality.
  • 6.2 Quality Standards 🔥:
    • 6.2.1 ISO 9000 Certification: Quality management standards & guidelines.
    • 6.2.2 Capability Maturity Model (CMM) 🔥 (5 Levels):
      Level 1: Initial (Ad-hoc, chaotic)
      Level 2: Repeatable (Basic Project Management)
      Level 3: Defined (Process Standardization across organization)
      Level 4: Managed (Quantitative Process Measurement)
      Level 5: Optimizing (Continuous Process Improvement & Defect Prevention)
    • 6.2.3 CMMI & PCMM: Staged vs Continuous representations.
    • 6.2.4 Six Sigma: DMAIC cycle & $3.4$ defects per million opportunities (DPMO).
  • 6.3 McCall's / ISO 9126 Quality Factors: Product Operation (Correctness, Reliability, Efficiency, Integrity, Usability), Revision (Maintainability, Flexibility, Testability), Transition (Portability, Reusability, Interoperability).

7. Software Testing 🔥🔥 [HIGH PRIORITY] TOP PRIORITY
  • 7.1 Verification vs Validation: Verification ("Are we building the product right?") vs Validation ("Are we building the right product?").
  • 7.2 Levels of Testing:
    • 7.2.1 Unit Testing: Testing individual modules/methods in isolation (Drivers & Stubs).
    • 7.2.2 Integration Testing: Top-down (uses Stubs), Bottom-up (uses Drivers), Big-Bang, Sandwich / Hybrid.
    • 7.2.3 System Testing: Functional, Performance, Stress, Load, Security, Recovery, Usability testing.
    • 7.2.4 Acceptance Testing: Alpha Testing (at developer's site by internal users) & Beta Testing (at client site by end users).
  • 7.3 Testing Techniques 🔥:
    • 7.3.1 White-box Testing (Structural / Clear-box): Statement Coverage, Branch / Decision Coverage, Path Coverage, Basis Path Testing using Cyclomatic Complexity.
    • 7.3.2 Black-box Testing (Functional / Opaque-box): Equivalence Partitioning (EP), Boundary Value Analysis (BVA — min, min+, nom, max-, max), Decision Table Testing, Cause-Effect Graphing.
    • 7.3.3 Grey-box Testing: Combination of structural knowledge & functional testing.
  • 7.4 Regression Testing vs Retesting: Re-running test cases to ensure new code changes haven't broken existing functionality.
  • 7.5 Debugging Approaches: Brute force, Backtracking, Cause elimination, Slicing.
  • 7.6 Test Case Design & Documentation: Test Plan, Test Case layout (ID, Description, Pre-conditions, Input data, Expected vs Actual Result, Status), Defect Lifecycle.

8. Software Maintenance & Re-engineering ✨
  • 8.1 Types of Maintenance (Categorization):
    • Corrective Maintenance: Reactive fixing of discovered bugs / errors (~20%).
    • Adaptive Maintenance: Modifying system to cope with environment / OS / DB changes (~20%).
    • Perfective Maintenance: Enhancing performance, maintainability, or adding new user requirements (~50% — highest share).
    • Preventive Maintenance: Proactive code refactoring to prevent future failures (~10%).
  • 8.2 Software Re-engineering Process: Inventory analysis, Document restructuring, Reverse engineering, Code restructuring, Data restructuring, Forward engineering.
  • 8.3 Reverse Engineering vs Forward Engineering: Extracting design specifications from source code vs traditional top-down development.
  • 8.4 Legacy Systems: Strategies for handling legacy software (Scrap, Maintain, Re-engineer, Replace).

9. CASE Tools (Computer-Aided Software Engineering) ✨
  • 9.1 Definition & Purpose: Automated software tool support for SDLC activities to improve productivity & quality.
  • 9.2 Types of CASE Tools:
    • Upper CASE Tools: Support early SDLC phases (Requirements analysis, System design, DFD/ERD modeling).
    • Lower CASE Tools: Support later SDLC phases (Code generation, Testing, Debugging, Documentation).
    • Integrated CASE (I-CASE) Tools: End-to-end support linking upper and lower CASE tools with a central repository.
  • 9.3 Examples & Role across SDLC: Requirement tools, Diagramming tools, Code generators, Test automation tools, SCM tools.
