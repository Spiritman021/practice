Section 18.1

What is Network Congestion?

Congestion occurs when the amount of data injected into a network by source hosts exceeds the handling capacity of intermediate routers and links. When router buffers overflow, packets are dropped, leading to retransmissions which worsen congestion!

📈
The Load vs Throughput Curve
• Light Load: Throughput increases proportionally with offering load.
• Knee Point: Load reaches network capacity; delay increases rapidly.
• Cliff Point: Congestion collapse! Routers drop packets continuously, throughput drops toward zero.

Section 18.2

Open-Loop vs Closed-Loop Control

Prevention
Open-Loop Congestion Control
Policies designed to **prevent** congestion before it happens. Takes action at sender or router design level. (Retransmission policy, Window policy, Traffic Shaping: Leaky/Token Bucket).
Removal
Closed-Loop Congestion Control
Mechanisms designed to **detect and remove** congestion after it occurs. (Choke packets, Implicit/Explicit Congestion Notification ECN, Backpressure).

18.3 Leaky Bucket Algorithm

The Leaky Bucket Algorithm shapes bursty traffic into a **smooth, constant-rate output stream**, like a bucket with a small hole at the bottom.

Working Mechanism

  • A fixed-capacity FIFO queue (bucket) holds incoming packets.
  • Incoming traffic arrives at irregular/bursty rates.
  • Packets leak out of the bottom at a strictly constant rate.
  • If the bucket overflows (capacity exceeded), new incoming packets are dropped.

18.4 Token Bucket Algorithm

The Token Bucket Algorithm allows **bursty traffic up to a maximum burst size**, providing flexibility while enforcing average rate limits.

Working Mechanism

  • Tokens are generated at a constant rate R and stored in a bucket with maximum capacity B.
  • To transmit a packet of size N bytes, the sender must remove N tokens from the bucket.
  • If enough tokens are available, the packet is sent immediately (allows full-speed burst).
  • If not enough tokens are available, the packet waits or is dropped.

Section 18.6

Choke Packets & RED (Random Early Detection)

1. Choke Packets

When a router experiences congestion, it sends a **Choke Packet** directly back to the source host instructing it to reduce its transmission rate.

2. RED (Random Early Detection)

An active queue management algorithm implemented in routers. Before queue capacity is 100% full, the router randomly drops a small percentage of incoming packets. This triggers TCP sources to lower their window size early, preventing global synchronization and severe buffer overflow!
