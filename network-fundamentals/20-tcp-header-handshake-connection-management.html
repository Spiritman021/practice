Section 20.1

TCP Overview & Features

TCP (RFC 793) is a connection-oriented, highly reliable, full-duplex protocol operating at the Transport Layer.

  • Connection-Oriented: Establishes a logical virtual circuit between sender and receiver before transferring data.
  • Byte-Stream Service: Treats data as a continuous stream of uninterpreted bytes, assigning a 32-bit sequence number to every byte.
  • Full-Duplex: Data can flow in both directions simultaneously over the same connection.
  • Reliable Delivery: Uses positive acknowledgements (ACKs) and retransmission timers (RTO) to recover lost or corrupted packets.
📦
Section 20.2

TCP Header Structure (20–60 Bytes)

The standard TCP Header contains 20 fixed bytes (and up to 40 bytes of optional parameters).

Key TCP Control Flags

  • SYN (Synchronize): Initiates a connection and synchronizes initial sequence numbers (ISN).
  • ACK (Acknowledgement): Indicates that the Acknowledgement Number field is valid.
  • FIN (Finish): Indicates that sender has finished transmitting data and requests connection termination.
  • RST (Reset): Immediately aborts an abnormal connection.
  • PSH (Push): Forces receiver to immediately push data to application without buffering.
  • URG (Urgent): Indicates that Urgent Pointer field is valid for urgent data payload.

Section 20.3

Connection Establishment: 3-Way Handshake

TCP establishes a connection between Client and Server using a **3-Way Handshake**:

  1. Step 1 (SYN): Client sends a SYN segment with Initial Sequence Number x to request a connection. Client enters SYN-SENT state.
  2. Step 2 (SYN-ACK): Server responds with a SYN-ACK segment, acknowledging Ack = x + 1 and proposing its own sequence number Seq = y. Server enters SYN-RCVD state.
  3. Step 3 (ACK): Client responds with an ACK segment (Ack = y + 1). Both sides enter ESTABLISHED state and data transfer begins!
🔴
Section 20.4

Connection Termination: 4-Way Handshake

Since TCP is full-duplex, terminating a connection requires closing each direction independently using a **4-Way Handshake**:

  • Step 1 (FIN from A): Client sends FIN segment to close its sending direction (Enters FIN-WAIT-1).
  • Step 2 (ACK from B): Server sends ACK (Client enters FIN-WAIT-2; Server enters CLOSE-WAIT).
  • Step 3 (FIN from B): Server finishes sending pending data and sends FIN segment (Server enters LAST-ACK).
  • Step 4 (ACK from A): Client sends final ACK and enters TIME-WAIT state for 2 × MSL (Maximum Segment Lifetime = ~4 minutes) before closing.
⏱️
Why the TIME-WAIT State (2 * MSL) Exists
1. Ensures the final ACK is received by the remote peer (retransmits ACK if lost).
2. Allows all old duplicate segments floating in the network to expire before a new socket connection reuses the same port pair.
⚙️
Section 20.5

TCP Connection State Machine

TCP StateDescription
CLOSEDNo connection active. Default starting state.
LISTENServer is waiting for an incoming SYN request.
SYN-SENTClient has sent SYN and is waiting for matching SYN-ACK.
SYN-RCVDServer received SYN, sent SYN-ACK, waiting for final ACK.
ESTABLISHEDConnection active; full-duplex data transfer in progress.
FIN-WAIT-1 / 2Client active close initiated; waiting for server ACK / FIN.
CLOSE-WAIT / LAST-ACKServer passive close; processing remaining data before final FIN.
TIME-WAITClient waiting 2*MSL to ensure clean closure before returning to CLOSED.
