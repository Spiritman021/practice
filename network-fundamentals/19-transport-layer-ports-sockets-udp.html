Section 19.1

Role of the Transport Layer

While the Network Layer delivers packets **Host-to-Host** (from source IP to destination IP), the Transport Layer is responsible for **Process-to-Process delivery** (delivering data to the specific application program running on that host).

Network Layer
Host-to-Host Delivery
Delivers packets across intermediate routers to the correct destination computer using IP addresses.
Transport Layer
Process-to-Process Delivery
Delivers segments to the exact software application (e.g. Browser, Email client) using Port numbers.
Exam Question Q85 Topic: Transport Layer Responsibilities
The transport layer in the OSI model is responsible for end-to-end __________ and error recovery across the network.
  • A. ✅ flow control ✓ Correct
  • B. encryption
  • C. routing
  • D. modulation
  • E. switching
Explanation: The Transport Layer (OSI Layer 4) provides process-to-process delivery, segment sequencing, flow control (using Sliding Window), and error recovery (ACKs & retransmissions).

Section 19.2

Port Addressing & Port Ranges

A Port Number is a 16-bit integer (ranging from 0 to 65535) used to identify a specific process/service on a network device.

Port CategoryRangeDescription & Well-Known Examples
Well-Known Ports 0 – 1023 Reserved for standard system protocols.
HTTP (80), HTTPS (443), SSH (22), FTP (20/21), DNS (53), SMTP (25), DHCP (67/68).
Registered Ports 1024 – 49151 Assigned by IANA for specific vendor applications.
MySQL (3306), PostgreSQL (5432), Redis (6379), RDP (3389).
Dynamic / Ephemeral Ports 49152 – 65535 Temporary ports assigned dynamically by client OS for outbound client connections.

Section 19.3

Socket Concept & Socket Pair

A Socket is an end-point for network communication, formed by combining an IP address and a Port number:

📍
Socket Definition & Socket Pair
$$ \text{Socket} = \text{IP Address} : \text{Port Number} \quad (\text{Example: } 192.168.1.10 : 80) $$ A unique network connection is defined by a 4-Tuple Socket Pair:
(Source IP, Source Port, Destination IP, Destination Port)

Section 19.4

UDP (User Datagram Protocol)

UDP (RFC 768) is an unreliable, connectionless, lightweight Transport Layer protocol. It provides minimal process-to-process communication with almost zero protocol overhead.

UDP Characteristics

  • Connectionless: No handshake prior to transmission; sender just fires datagrams.
  • Unreliable: No acknowledgements (ACKs), no retransmission of lost packets, no sequence ordering.
  • Stateless: Neither sender nor receiver maintains connection state.
  • Supports Unicast, Multicast & Broadcast: Unlike TCP (unicast only), UDP can send packets to multiple destinations.
  • Low Latency / High Speed: Ideal for real-time applications where speed is preferred over reliability.

Common UDP Applications

DNS (Domain Name System), VoIP (Voice over IP), Video Streaming (IPTV, YouTube live), Online Gaming, DHCP, TFTP, SNMP.

📦
Section 19.5

UDP 8-Byte Header Structure

The UDP header consists of exactly 8 bytes (64 bits) divided into four 16-bit fields:

  • Source Port (16 bits): Port of sending application (optional in UDP; set to 0 if unused).
  • Destination Port (16 bits): Port of receiving application.
  • Length (16 bits): Total length of UDP datagram (Header + Payload) in bytes. Minimum value = 8.
  • Checksum (16 bits): Detects errors in UDP header, payload, and IP pseudo-header.

Exam Question Q76 Topic: TCP vs UDP Protocol Characteristics
Which of following given statement is /are correct?
P: TCP does not support multicasting and broadcasting.
Q: UDP only support broadcasting.
R: UDP is fast because it does not wait for any sequence.
  • A. Only P
  • B. Only Q
  • C. Both P & Q
  • D. Only R
  • E. ✅ Both P & R ✓ Correct
Explanation:
• P is TRUE: TCP is strictly point-to-point (unicast only). It cannot perform multicast or broadcast.
• Q is FALSE: UDP supports unicast, multicast, and broadcast (not only broadcast).
• R is TRUE: UDP is fast because it is connectionless and doesn't wait for sequence ordering or ACKs.
