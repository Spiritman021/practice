Section 23.1

WWW & URL Anatomy

A URL (Uniform Resource Locator) specifies the exact address of a web resource on the World Wide Web.

🔍
URL Structure Breakdown
https :// www.example.com : 443 / pages / index.html ? user=123 # section2
  • Scheme / Protocol: https (specifies communication protocol).
  • Host / Domain Name: www.example.com (resolved to IP address by DNS).
  • Port Number: :443 (optional; default 80 for HTTP, 443 for HTTPS).
  • Path: /pages/index.html (path to target file on web server).
  • Query Parameters: ?user=123 (key-value pairs sent to server).
  • Fragment / Anchor: #section2 (client-side bookmark location).

23.6 FTP (Active/Passive) & TFTP Protocols

1. FTP (File Transfer Protocol - TCP 20/21)

FTP uses two separate TCP connections (In-band control, Out-of-band data):

  • Control Connection (TCP Port 21): Used for sending commands and authentication credentials. Remains open throughout session.
  • Data Connection (TCP Port 20 / Ephemeral): Opened dynamically whenever a file is uploaded or downloaded.

Active Mode vs Passive Mode:

  • Active FTP: Client connects to Port 21; Server initiates data connection back to client from Port 20. (Fails behind client firewalls/NAT!).
  • Passive FTP (PASV): Client connects to Port 21; Server opens random unprivileged port and client initiates data connection to server. (Firewall friendly).

2. TFTP (Trivial File Transfer Protocol - UDP 69)

A minimal, lightweight file transfer protocol using UDP Port 69. Does NOT support authentication, directory listing, or encryption. Used for booting diskless workstations (PXE boot) and flashing router firmware.
