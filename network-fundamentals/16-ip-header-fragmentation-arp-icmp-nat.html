Section 16.1

IPv4 Header Structure

The standard IPv4 Datagram Header consists of 20 fixed bytes (up to 60 bytes with optional fields).

Key Field Definitions

  • IHL (Internet Header Length): Specifies header length in 32-bit words (Default = 5, i.e. 5 × 4 = 20 Bytes).
  • TTL (Time to Live): Decremented by 1 at every router hop. Prevents packets from circulating indefinitely in routing loops (when TTL = 0, packet is dropped and ICMP Time Exceeded sent).
  • Protocol: Identifies upper layer payload protocol (6 = TCP, 17 = UDP, 1 = ICMP).
  • Flags: 3 bits — Bit 0: Reserved; Bit 1: DF (Don't Fragment); Bit 2: MF (More Fragments).
  • Fragment Offset: Indicates relative position of fragment payload in 8-byte blocks.
Exam Question Q79 Topic: IPv4 Header TTL & ICMP Protocol
When a router receives a packet whose TTL becomes zero after decrementing, what action does it typically take?
  • A. Resets TTL to default value
  • B. Sends packet back to previous router
  • C. ✅ Drops the packet and sends an ICMP Time Exceeded message ✓ Correct
  • D. Broadcasts packet to all neighbors
  • E. Converts the packet to multicast
Explanation: Every router decrements the TTL field by 1. When TTL reaches 0, the router discards the packet to prevent infinite loops and sends an ICMP Type 11 (Time Exceeded) error message back to the source IP.

Section 16.2

IP Packet Fragmentation & Reassembly

When an IP datagram's total size exceeds the link layer's **MTU (Maximum Transmission Unit)** (e.g. 1500 bytes for Ethernet), intermediate routers divide the datagram into smaller **Fragments**.

Reassembly of fragments occurs ONLY at the ultimate destination host.

🧮
Fragment Offset Calculation Formula
Fragment Offset = Cumulative Data Bytes Before This Fragment / 8
Note: Every fragment payload size (except last) MUST be a multiple of 8 bytes!

Section 16.3

ARP & RARP Protocols

ARP (Address Resolution Protocol) maps a known logical 32-bit IP address to an unknown physical 48-bit MAC address on the local network.

ARP Working Mechanism

  1. Host A wants to send data to IP B on local LAN. It checks its local **ARP Cache Table**.
  2. If IP B is not in cache, Host A broadcasts an **ARP Request** ("Who has IP 192.168.1.50? Tell 192.168.1.10") using Destination MAC FF:FF:FF:FF:FF:FF.
  3. Host B recognizes its IP and replies with a unicast **ARP Reply** ("192.168.1.50 is at 00:1A:2B:3C:4D:5E").
  4. Host A updates its ARP cache table and transmits data.

Section 16.4

ICMP (Ping & Traceroute Mechanics)

ICMP (Internet Control Message Protocol) is used by network devices (routers, hosts) to communicate diagnostic error and control messages.

1. How PING Works

Sends an **ICMP Echo Request (Type 8)** to a target IP. Target responds with an **ICMP Echo Reply (Type 0)**. Measures Round-Trip Time (RTT) and packet loss.

2. How TRACEROUTE Works

Traceroute discovers the step-by-step router path to a destination using the **TTL field**:

  1. Sends 1st packet with TTL = 1. Router 1 decrements TTL to 0, drops packet, and sends back an **ICMP Time Exceeded (Type 11)** message. (Router 1 IP discovered!).
  2. Sends 2nd packet with TTL = 2. Router 2 drops packet → ICMP Time Exceeded. (Router 2 IP discovered!).
  3. Repeats with incrementing TTL until packet reaches target host and receives **Port Unreachable (Type 3)** response.

Section 16.5

NAT & PAT (Network Address Translation)

NAT translates private RFC 1918 IP addresses (e.g. 192.168.1.x) into a single public IP address when traffic crosses a router toward the Internet.

Types of NAT

  • Static NAT: 1-to-1 mapping between 1 private IP and 1 public IP. (Used for hosting public web servers).
  • Dynamic NAT: Maps private IPs to a pool of public IPs on a first-come, first-served basis.
  • PAT (Port Address Translation / NAT Overload): Maps thousands of private IPs to a SINGLE public IP by assigning a unique Source Port number to each private connection. (Used in home routers).
