25.1 SNMP Architecture Overview

SNMP (Simple Network Management Protocol) is an application-layer protocol used to monitor, configure, and manage network devices (routers, switches, firewalls, servers).

Core SNMP Components

  • NMS (Network Management Station / Manager): Central management system running monitoring software (e.g. Nagios, Zabbix, SolarWinds). Queries agents and receives alerts.
  • SNMP Agent: Software module running on managed network devices (routers, switches). Collects local status metrics and responds to manager queries.
  • MIB (Management Information Base): Virtual database containing hierarchical data variables supported by the managed device.

Section 25.2

MIB (Management Information Base) & OID Structure

MIB data variables are organized in a **hierarchical tree structure**. Every variable is uniquely identified by an **OID (Object Identifier)** string of numbers separated by dots.

📌
OID Example Breakdown
.1.3.6.1.2.1.1.5.0  →  iso.org.dod.internet.mgmt.mib-2.system.sysName.0

This specific OID retrieves the hostname (sysName) of the managed router/switch.

Section 25.3

SNMP Operations & Message Types

SNMP operates over **UDP Ports 161 (Manager-to-Agent requests)** and **UDP Port 162 (Unsolicited Agent Traps)**:

SNMP OperationInitiatorUDP PortDescription
GetRequestManager → Agent161Retrieves the value of a specific MIB OID variable.
GetNextRequestManager → Agent161Retrieves the next sequential OID variable in the MIB tree.
SetRequestManager → Agent161Modifies/configures a MIB variable on the managed device.
GetResponseAgent → Manager161Returns requested values or status results to the Manager.
TrapAgent → Manager162Unsolicited alert sent immediately by Agent upon critical event (e.g., Interface Down, Power Supply Failure).
InformRequestManager → Manager162Acknowledged alert message sent between managers.
