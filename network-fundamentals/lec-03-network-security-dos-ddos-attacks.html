3.1 DoS & DDoS Attack Overview & CIA Violation

In a Denial of Service (DoS) or Distributed Denial of Service (DDoS) attack, attackers overwhelm a server, network device, or communication link with a massive flood of malicious traffic, causing it to slow down, crash, or become completely unresponsive to legitimate users.

⚠️ Core Security Principle Violated

DoS and DDoS attacks directly target and violate the AVAILABILITY pillar of the CIA Triad (Confidentiality, Integrity, Availability). They do not steal or alter data; rather, they render services unusable.

1. DoS (Denial of Service)
• Originates from a SINGLE source IP / single device.
• Attacks the target by maxing out bandwidth or CPU.
• Detection: Relatively easy to detect and block at the firewall by blacklisting the single offending IP address.
2. DDoS (Distributed Denial of Service)
• Originates from MULTIPLE sources / Botnets (thousands of compromised computers & IoT devices).
• Generates multi-gigabit or terabit-scale traffic floods.
• Detection: Extremely difficult to mitigate because traffic comes from thousands of valid global IP addresses simultaneously.
🔥 HIGH YIELD EXAM TOPIC · IMPORTANT

3.2 Major Flood Attack Vectors

Attackers utilize various protocol-specific flood mechanisms across different OSI layers:

Attack Vector OSI Operating Layer Attack Mechanism & Exploitation Details Impact & Characteristics
ICMP Flood (Ping Flood) Layer 3 (Network) Sends continuous flood of ICMP Echo Request packets to victim IP without waiting for replies. Consumes victim's incoming/outgoing network bandwidth and CPU processing capacity.
UDP Flood Layer 4 (Transport) Floods random destination UDP ports on victim host with UDP packets. Receiver checks for non-existent apps and generates ICMP "Destination Unreachable". Overwhelms network socket tables and CPU resources. High volume, connectionless.
TCP SYN Flood Layer 4 (Transport) Exploits the TCP 3-Way Handshake. Attacker sends SYN packets with spoofed IPs. Server replies with SYN-ACK and allocates memory in SYN Connection Backlog Queue waiting for final ACK (which never arrives!). Fills connection queue with half-open connections, blocking legitimate TCP connections. High-yield exam topic!
HTTP Flood Layer 7 (Application) Sends flood of seemingly valid HTTP GET or POST requests targeting resource-intensive database queries or heavy search scripts. Exhausts web server CPU, memory, and database connections. Low bandwidth requirement, hard to distinguish from normal users.

3.3 Case Study: Mirai Botnet & 2016 Dyn DNS Attack

🔥 HIGH-YIELD IBPS SO IT TOPIC
🚨

The 2016 Dyn DNS DDoS Incident (Must-Know Exam Fact)

In October 2016, one of the largest DDoS attacks in history targeted Dyn, a major Domain Name System (DNS) provider.

  • The Mirai Botnet Vector: Mirai scanned the internet for unsecured Internet of Things (IoT) devices (IP security cameras, home routers, DVRs) protected only by factory default usernames and passwords (e.g. admin/admin).
  • Infection & Command: Over 600,000 compromised IoT devices were recruited into a coordinated botnet army controlled by Command & Control (C2) servers.
  • Massive Impact: The botnet launched a multi-terabit DNS query flood against Dyn, crashing DNS resolution across North America and Europe. Major platforms including Twitter, Netflix, Reddit, GitHub, Airbnb, and Spotify suffered widespread outages.
  • 🔥 Key Exam Takeaway: Highlights the risk of unpatched IoT devices and single points of failure in critical core internet infrastructure (DNS). Repeatedly tested in IBPS SO IT exams!

3.4 DoS vs DDoS Master Comparison Table

Comparison Parameter DoS (Denial of Service) DDoS (Distributed Denial of Service)
Attack Source Count Single source (1 computer / 1 IP address). Multiple sources (thousands of botnet zombie devices & IPs).
Scale of Attack Smaller scale (limited by single machine capacity). Massive scale (Gigabits to Terabits/sec - Tbps).
Tools Used 🔥 (IMPORTANT) LOIC (Low Orbit Ion Cannon), HOIC, Slowloris, hping3.
🔥 TOP EXAM FACT Botnets (Mirai, Necurs),
Amplification servers (NTP, DNS).
Ease of Detection & Blocking Easier to block: Firewall blacklists the single attacking IP address. Extremely difficult: Traffic originates from millions of valid global IPs.
Resource Requirement Low resources (requires only 1 machine). High resources (requires establishing & maintaining botnet infra).
Business Impact Temporary slowness, manageable with basic filters. Severe, network-wide crippling outages & financial losses.

3.5 Defense & Mitigation Strategies

Effective defense against DoS and DDoS attacks requires a multi-layered defense-in-depth architecture:

1. Firewalls & IPS Inline Defense

Inline Firewalls and Intrusion Prevention Systems (IPS) monitor traffic patterns, block malformed packets, and use signature/behavioral rules to drop malicious attack streams.

2. Rate Limiting

Restricts the maximum number of requests a single client IP address can make within a specified time window (e.g. max 100 HTTP requests per minute). Prevents application-layer flooding.

3. Load Balancing & Redundancy

Distributes incoming traffic across redundant backend web server farms, absorbing traffic spikes and preventing any single server from crashing.

4. SYN Cookies (SYN Flood Mitigation)

Encodes connection state parameters into the initial TCP sequence number in the SYN-ACK packet. Eliminates the need to allocate server memory until the final ACK arrives!

☁️ Cloud Traffic Scrubbing & Anycast Routing

DDoS protection providers (e.g. Cloudflare, Akamai, AWS Shield) use BGP Anycast routing to divert incoming traffic to global Scrubbing Centers. Malicious botnet traffic is identified and dropped at the scrubbing cloud, while clean legitimate traffic is forwarded to the origin server.

3.7 Quick Exam Revision Cheat Sheet

1. CIA Pillar: DoS and DDoS directly violate Availability.

2. DoS vs DDoS: DoS = 1 Source IP (Easy to block). DDoS = Botnets / Thousands of Source IPs (Hard to block).

3. Floods by Layer:
• ICMP Ping Flood = Layer 3 (Network)
• UDP Flood = Layer 4 (Transport)
• TCP SYN Flood = Layer 4 (Exhausts 3-way handshake SYN Queue)
• HTTP Flood = Layer 7 (Application - CPU/Database exhaustion)

4. Mirai Botnet: 2016 Dyn DNS attack using compromised IoT devices (cameras/routers with default passwords).

5. Defensive Controls: Rate Limiting (regulates request frequency), Load Balancing (distributes traffic), SYN Cookies (mitigates SYN floods), Cloud Traffic Scrubbing (Anycast filtering).

Flood Attacks – In-Depth Exam Study Guide

OSI Layer Breakdown, Handshake Mechanisms & IBPS SO IT Exam Shortcuts
💡
Core Flood Attack Concept
Attacker sends a huge number of requests/packets → victim's resources get exhausted → genuine users cannot access the service.
The main difference between these attacks is what type of traffic is being flooded and which OSI layer is targeted.
1

ICMP Flood / Ping Flood

Layer 3 – Network Layer
Simple Idea

The attacker continuously sends Ping (ICMP Echo Request) packets to the victim.

Client → "Are you alive?" (Ping)
Server → "Yes, I am!" (Reply)
In a Ping Flood: Attacker ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ → Victim (thousands/millions of requests)
What Happens?

The victim has to process all those packets and generate replies.

Huge ICMP traffic → CPU + bandwidth consumed → legitimate traffic becomes slow/unavailable
📌
OSI Layer: Layer 3 – Network Layer (ICMP works along with IP at the network layer).
Remember: ICMP Flood = Flood with Ping packets.
Exam Keyword: Ping Flood → ICMP → Layer 3
2

UDP Flood

Layer 4 – Transport Layer

UDP is a connectionless protocol (doesn't establish a connection before sending data). The attacker sends lots of UDP packets to random ports.

Attacker ↓
UDP packet → Port 1000
UDP packet → Port 2000
UDP packet → Port 3000
UDP packet → Port 4000
↓ Victim

If the victim doesn't have an application listening on a port, the OS responds with: ICMP Destination Unreachable.

Receive UDP packet → Check destination port → No application? → Generate ICMP error → Repeat millions of times

Result: CPU and network resources get exhausted.

📌
OSI Layer: Layer 4 – Transport Layer (UDP is a transport protocol).
Remember: UDP Flood = Huge number of UDP packets → victim checks ports → resources exhausted.
Exam Keyword: UDP → Layer 4 → Connectionless
3

TCP SYN Flood ⭐ VERY IMPORTANT

Layer 4 – Transport Layer

This is one of the most important attacks for exams. First understand the TCP 3-Way Handshake:

Client      SYN →          Server
Client      ← SYN-ACK      Server
Client      ACK →          Server → (Connection established)

SYN = Synchronize: Used to start a TCP connection.

What Happens in SYN Flood?

The attacker sends lots of SYN requests. The server responds with SYN-ACK and waits for the final ACK. But the attacker NEVER sends the final ACK!

SYN received → SYN-ACK sent → Waiting for ACK... (Waiting... Waiting...) → Connection backlog queue full → Legitimate users blocked
Why is it called "Half-Open"?
SYN    ✓
SYN-ACK    ✓
ACK    ✗
⇒ Half-open connection
Remember This Sequence ⭐
SYN Flood → Many SYNs → Server sends SYN-ACK → ACK never comes → Half-open connections → Backlog queue full → Legitimate users blocked
⭐
OSI Layer: Layer 4 – Transport Layer.
Exam Keywords: SYN Flood → TCP → 3-way handshake → Half-open connections → Backlog queue → Layer 4
4

HTTP Flood

Layer 7 – Application Layer

This attack targets the application itself. Imagine a website operation: Search → Database query → Process results → Return page.

The attacker sends huge numbers of apparently normal HTTP requests:

GET /search?q=computer
GET /search?q=network
GET /search?q=security
GET /search?q=database → Server

An attacker might generate 100,000 requests/minute compared to 5/minute from a normal user!

HTTP Requests → Web Server → Application → Database → CPU + RAM + DB connections exhausted
Why is HTTP Flood Dangerous?

Traffic looks like normal web traffic. The attacker makes the server do expensive work rather than just consuming raw network bandwidth.

📌
OSI Layer: Layer 7 – Application Layer (HTTP is an application protocol).
Remember: HTTP Flood = Make the web server work too much.
Exam Keywords: HTTP Flood → HTTP GET/POST → Layer 7 → CPU/Memory/Database exhaustion

⭐ IBPS SO IT Exam Points (Must Memorize)

  • 1. ICMP Flood: Also called Ping Flood | Protocol: ICMP | Layer: Network / Layer 3
  • 2. UDP Flood: Protocol: UDP | Layer: Transport / Layer 4 | UDP is connectionless
  • 3. TCP SYN Flood: Protocol: TCP | Layer: Transport / Layer 4 | Exploits 3-way handshake | Creates half-open connections | Fills SYN backlog connection queue
  • 4. HTTP Flood: Protocol: HTTP | Layer: Application / Layer 7 | Uses massive GET/POST requests | Exhausts CPU, memory & DB connections
One-line Memory Trick:
Ping = L3, UDP = L4, SYN = L4, HTTP = L7
Most Important Distinction:
SYN Flood attacks the TCP connection establishment process, whereas HTTP Flood attacks the application/web-server workload.
