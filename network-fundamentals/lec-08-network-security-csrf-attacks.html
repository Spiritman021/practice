8.1 What is Cross-Site Request Forgery (CSRF)?

Cross-Site Request Forgery (CSRF or XSRF), also known as "Session Riding", is an attack that tricks an already authenticated user into submitting unintended, unauthorized HTTP commands to a web application where they currently hold an active session.

🔑 Exploitation of Ambient Authority

CSRF exploits the implicit trust a web application places in requests coming from an authenticated user's browser. The server processes the forged request believing it originated intentionally from the user.

🌐 Automatic Cookie Transmission

By default, browsers automatically include domain session cookies with EVERY HTTP request sent to that target domain, regardless of which external website initiated the request!

8.2 Step-by-Step 6-Stage Bank Transfer Scenario

Detailed breakdown of the exact 6-step attack flow from PDF Slide 2 (Rahul vs. Bablu):

1

Victim Logs In & Establishes Active Session

Rahul logs into his bank website (bank.com). The bank allows fund transfers via URL GET requests: https://bank.com/transfer?to=monu&amount=100. Rahul's browser stores his session cookie (session_id=abc123).

2

Attacker Creates Malicious Website

Attacker (Bablu) sets up a malicious external site (bablu.com) hosting a hidden CSRF exploit payload.

3

Phishing Trap Email Sent

Bablu sends Rahul an enticing phishing email: "You won ₹1000 Cashback! Click here to claim!" containing a link to bablu.com.

4

Hidden Image Exploit Tag Encoded

When Rahul clicks the link and opens bablu.com, the page contains a hidden HTML image tag targeting the bank:

<img src="https://bank.com/transfer?to=Eve&amount=100" style="display:none;">
5

Automatic Browser Cookie Attachment

Rahul's browser tries to render the image. Seeing the `src` domain is bank.com, the browser automatically attaches Rahul's active session cookie (Cookie: session_id=abc123) to the outgoing GET request!

6

Bank Executes Unauthorized Money Transfer

The server at bank.com receives the GET request with a valid session cookie. Believing Rahul initiated it, the bank executes the transfer of ₹100 to Eve/Bablu without Rahul's knowledge!

8.3 XSS vs. CSRF Master Comparison Table

Distinguishing XSS from CSRF is a frequent IBPS SO IT exam topic:

Comparison Parameter Cross-Site Scripting (XSS) Cross-Site Request Forgery (CSRF)
Exploited Trust Direction Exploits user's trust in a vulnerable website. Exploits website's trust in a user's browser.
Payload Execution Location Executes malicious JavaScript inside victim's browser. Sends forged HTTP requests to vulnerable target server.
Cookie Handling Reads / Steals document cookies via JS (document.cookie). Cannot read cookies; relies on browser auto-attaching them.
Primary Defense HTML Entity Encoding & Content Security Policy (CSP). Anti-CSRF Tokens & SameSite Cookie Attributes.

8.4 How to Fix & Prevent CSRF (Anti-CSRF Tokens, SameSite)

1. Anti-CSRF Synchronizer Tokens ⭐

The #1 Defense against CSRF! The server generates a unique, unpredictable, secret token tied to the user's current session and embeds it in HTML forms as a hidden field:

<form action="/transfer" method="POST">
  <input type="hidden" name="csrf_token" value="d9K3mP8zL1qR...">
  <!-- Form fields -->
</form>

Attacker sites cannot read this token due to Same-Origin Policy (SOP). Forged requests without a valid csrf_token are immediately rejected by the server!

2. SameSite Cookie Attributes ⭐

Configures browser cookie sharing behavior for cross-site requests:

  • SameSite=Strict: Cookie is NEVER sent in cross-site requests (highest security).
  • SameSite=Lax: Withholds cookies on cross-site sub-requests (like <img> or <iframe> src calls).

3. Validate Origin / Referer Headers

Server verifies that Origin: or Referer: HTTP headers match the expected domain (bank.com).

4. Use HTTP POST & Re-Authentication

Never perform state changes via GET. Require OTP / password re-entry for critical financial operations.

C) Command Injection

Correct Answer: B) Cross-Site Request Forgery (CSRF).
Explanation: CSRF tricks an authenticated user into executing unwanted actions on a trusted site by leveraging automatic browser cookie transmission.
