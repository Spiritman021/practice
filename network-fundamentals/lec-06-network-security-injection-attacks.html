6.1 What is an Injection Attack?

An Injection Attack occurs when an attacker inputs untrusted, malicious code or syntax into an application's input field or query interpreter. The interpreter mistakenly executes the untrusted data as command code, leading to unauthorized data access or system takeover.

🗄️ SQL Injection (SQLi)

Injects database queries to bypass login forms, dump database contents, or modify data tables.

💻 OS Command Injection

Tricks applications into executing terminal commands directly on the host operating system.

🌐 Cross-Site Scripting (XSS)

Injects malicious client-side JavaScript executed inside victim browser sessions.

6.2 SQL Injection (SQLi) & Authentication Bypass

SQL Injection is one of the most dangerous web application vulnerabilities. It occurs when un-sanitized user input is directly concatenated into SQL query strings.

🔓 The Classic Login Authentication Bypass

Original vulnerable backend SQL query string:

SELECT * FROM users WHERE username = '[user_input]' AND password = '[password_input]';

Attacker inputs into Username field: admin' --

SELECT * FROM users WHERE username = 'admin' --' AND password = '';

Or inputs into Username field: ' OR 1=1 --

SELECT * FROM users WHERE username = 'user' OR 1=1 --' AND password = '';
• The Single Quote ('): Breaks out of the intended SQL string literal.
• The Tautology (OR 1=1): Evaluates to TRUE for every row in the database.
• The Comment Indicator (-- or #): Comments out the rest of the query, ignoring password verification entirely!

6.3 OS Command Injection & Shell Execution Exploits

OS Command Injection occurs when an application passes un-sanitized user input into system-level shell calls (`os.system`, `exec`, `popen`).

💻 Python OS Command Execution Vulnerability Example

# Vulnerable Python Function (From PDF Slide 3)
import os

def check_disk_space(path):
    os.system(f"df -h {path}")
• Normal Safe Input: /home/user $\rightarrow$ System executes: df -h /home/user
• Malicious Injected Input: /home/user; rm -rf / $\rightarrow$ System executes: df -h /home/user; rm -rf /
• Result: Command separator semicolon (;) or ampersand (&&) allows execution of arbitrary destructive terminal commands with server OS privileges!

6.4 4 Key Defense Mitigations (Prepared Statements, WAF, PoLP)

1. Parameterized Queries / Prepared Statements ⭐

The #1 Defense against SQLi! Separates SQL code logic from user data. Database engine treats user input strictly as literal parameter data, never as executable code.

# Vulnerable Code (String Concatenation)
user_id = input("Enter user ID:")
query = f"SELECT * FROM users WHERE id = {user_id}"
cursor.execute(query)
# Safe Code (Parameterized Query)
user_id = input("Enter user ID:")
query = "SELECT * FROM users WHERE id = ?"
cursor.execute(query, (user_id,))

2. Input Sanitization & Validation

Enforce strict allowlists, data type checking (e.g. ensure ID is integer), and HTML/SQL special character escaping.

3. Web Application Firewalls (WAF)

Inspects HTTP payloads at Layer 7 to detect and drop malicious injection vectors (e.g. AWS WAF, Cloudflare).

4. Principle of Least Privilege (PoLP)

Restricts database user privileges to only required tables and operations:

GRANT SELECT ON employees TO public_user;
GRANT SELECT, INSERT, UPDATE ON payroll TO hr_user;

6.5 IBPS SO IT Verified Solved Question Bank

IBPS SO IT 2023 Verified
Q1. Which of the following is considered the MOST effective software development defense against SQL Injection (SQLi) attacks?
A) Client-side JavaScript validation
B) Parameterized Queries / Prepared Statements ✓
C) Storing passwords as plain text
D) Packet Filtering Firewalls
Correct Answer: B) Parameterized Queries / Prepared Statements.
Explanation: Prepared statements separate database query logic from data parameters, preventing user input from ever being executed as SQL syntax.
IBPS SO IT 2022 Verified
Q2. What is the primary objective of an attacker entering `' OR '1'='1` or `' --` into a web application login field?
A) To execute a Denial of Service attack on the database
B) To bypass login authentication via SQL Injection ✓
C) To perform Cross-Site Scripting (XSS)
D) To brute-force the server SSH password
Correct Answer: B) To bypass login authentication via SQL Injection.
Explanation: The `' OR 1=1` forces the SQL query WHERE clause to evaluate to TRUE, while `--` comments out password verification.
IBPS SO IT 2020 Verified
Q3. Passing un-sanitized user input strings directly into system functions like `os.system()` or `exec()` makes an application vulnerable to:
A) Cross-Site Request Forgery
B) OS Command Injection ✓
C) Buffer Overflow
D) Session Hijacking
Correct Answer: B) OS Command Injection.
Explanation: OS Command Injection allows attackers to append arbitrary operating system terminal commands (e.g. `; rm -rf /`) onto shell system calls.
IBPS SO IT 2024 Verified
Q4. Restricting database user permissions to only required tables using statements like `GRANT SELECT ON employees TO public_user;` follows which security principle?
A) Defense in Depth
B) Principle of Least Privilege (PoLP) ✓
C) Fail-Safe Defaults
D) Open Design Principle
Correct Answer: B) Principle of Least Privilege (PoLP).
Explanation: PoLP dictates that user accounts and processes should be granted only the minimum permissions necessary to complete their job functions.

6.6 Quick Exam Revision Cheat Sheet

1. Injection Attacks: Occur when untrusted user input is executed as code by a backend query or shell interpreter.

2. SQLi Auth Bypass: ' OR 1=1 -- forces query evaluation to TRUE and comments out password checking.

3. OS Command Injection: Exploits un-sanitized input in os.system() using command separators like ; or && (e.g., path; rm -rf /).

4. #1 Defense against SQLi: Parameterized Queries / Prepared Statements (query = "SELECT * FROM users WHERE id = ?").

5. Layer 7 Defense: Web Application Firewall (WAF) drops malicious HTTP injection payloads.

6. Permission Control: Principle of Least Privilege (PoLP) via SQL GRANT SELECT statement restrictions.
