Security Attacks — Passive vs Active TOP PRIORITY 🔥🔥
Two fundamental categories — what they target
👁 Passive Attack

Attacker only observes — does NOT modify data

  • Eavesdropping
  • Traffic analysis
  • Sniffing (packet capture)
🎯 Main Target
Confidentiality
⚡ Active Attack

Attacker modifies / disrupts communication

  • Modification
  • Masquerade (spoofing identity)
  • Replay attack
  • DoS / DDoS
🎯 Main Targets
Integrity + Availability
⭐ Key Distinction
Passive attacks are hard to detect (no modification). Active attacks are easier to detect but harder to prevent completely.

Common Network Attacks TOP PRIORITY 🔥🔥
DoS, MITM, Spoofing, Phishing, SQLi, XSS, CSRF, Buffer Overflow & more
🚫 DoS & DDoS
  • DoS → One/few sources overwhelm a service to make it unavailable
  • DDoS → DoS from many compromised systems (botnet) simultaneously
🎮 Spoofing

Attacker pretends to be someone/something else

  • IP spoofing
  • MAC spoofing
  • Email spoofing
  • DNS spoofing
👮 Man-in-the-Middle (MITM)
Alice ↔ [Attacker] ↔ Bob

Secretly intercepts (and possibly modifies) communication between two parties.

🔁 Replay Attack

Captures a valid message and re-sends it later to trick the system into unauthorized access.

📷 Sniffing

Passively capturing network packets. Tools: Wireshark, tcpdump. Passive attack.

🔗 Session Hijacking

Attacker steals an active authenticated session token to impersonate the logged-in user.

📧 Phishing & Social Engineering
  • Phishing → Fake email/site to steal credentials
  • Pharming → Redirects via DNS manipulation to fake site
  • Vishing → Voice-based phishing
  • Smishing → SMS-based phishing
  • Baiting & Pretexting → Manipulating human psychology
🌎 Zero-Day Attack NEW

Exploits a vulnerability that is unknown to the vendor — no patch exists yet. Extremely dangerous.

Application-Layer Attacks (Expanded) NEW
📈 SQL Injection (SQLi)

Injects malicious SQL code through an input field to manipulate or extract database contents.

Input: ' OR '1'='1 → Bypasses login / dumps database

Defense: Parameterized queries, input validation, least-privilege DB accounts

🔨 Cross-Site Scripting (XSS)

Attacker injects malicious script into a webpage that runs in other users' browsers.

Types: Stored XSS, Reflected XSS, DOM-based XSS

Defense: Output encoding, input sanitization, Content Security Policy (CSP)

🔁 CSRF — Cross-Site Request Forgery

Tricks an already-authenticated user's browser into submitting an unwanted request to a site they're logged into.

Defense: CSRF tokens, SameSite cookies

💥 Buffer Overflow

Writing more data into a buffer than it can hold → overwrites adjacent memory → crashes or arbitrary code execution.

Defense: Bounds checking, ASLR, stack canaries, safe functions

Cryptography Overview TOP PRIORITY 🔥🔥
Symmetric, Asymmetric, Hashing — Cryptography vs Steganography
Cryptography = provides secure communication using mathematical techniques to protect Confidentiality, Integrity, and Authenticity of data.
Basic Encryption Flow
Plaintext→Encryption→Ciphertext→Decryption→Plaintext
Three Core Cryptographic Techniques
🔐 Symmetric

Same key for encryption & decryption. Fast. Key distribution problem.

🔓 Asymmetric

Public + Private key pair. Slower. Solves key distribution.

📋 Hashing

One-way. Fixed-length digest. Cannot be reversed.

Cryptography vs Steganography NEW
CryptographySteganography
Hides the content/meaning of a messageHides the existence of the message itself
Data looks scrambled/encryptedData looks like a normal file (image, audio, video)

Symmetric Key Cryptography TOP PRIORITY 🔥🔥
Same key used for both encryption and decryption — AES, DES, 3DES, Blowfish
Symmetric Key Flow
Plaintext→Encrypt + Secret Key→Ciphertext→Decrypt + Same Secret Key→Plaintext
✓ Advantages
  • Fast & computationally efficient
  • Suitable for large volumes of data
✗ Disadvantage

Key Distribution Problem → Both parties must securely exchange the shared secret key beforehand.

Common Algorithms & Details
AlgorithmBlock SizeKey SizeStatus
DES64 bits56 bits effective✘ Insecure (key too small)
3DES64 bits112 / 168 bits⚠ Deprecated (slow)
AES ⭐128 bits128 / 192 / 256 bits✓ Strong — widely used
Blowfish64 bits32–448 bits✓ Good (historical use)
⭐ AES Key Facts
AES block size = 128 bits always. Key sizes = 128, 192, or 256 bits. AES-256 is much stronger than DES.

Asymmetric Cryptography TOP PRIORITY 🔥🔥
Public + Private key pair — RSA, ECC — Encryption & Digital Signature rules
Uses two mathematically linked keys: Public Key (shared openly) + Private Key (kept secret). Solves the key distribution problem of symmetric cryptography.
🔒 For Confidentiality (Sending Encrypted Data)
Alice → Encrypt with BOB'S PUBLIC KEY → Ciphertext (only Bob can decrypt) → Bob decrypts with HIS PRIVATE KEY

Encrypt with receiver's PUBLIC key ⭐

✏ For Digital Signature (Auth / Non-repudiation)
Alice → Sign with HER PRIVATE KEY → Signature attached to message → Bob verifies with ALICE'S PUBLIC KEY

Sign with sender's PRIVATE key ⭐

⭐ Golden Rules — Must Memorize!
Encryption for confidentiality → use receiver's PUBLIC key
Digital Signature → use sender's PRIVATE key
Common Algorithms
  • RSA → Most widely used asymmetric algorithm (encryption + signatures)
  • ECC (Elliptic Curve Cryptography) → Smaller keys, same security, more efficient
  • Diffie-Hellman → Key exchange algorithm (not encryption directly)

Hashing HIGH YIELD
One-way fixed-length digest — MD5 broken, SHA-256 good
Hash function converts input data of any size into a fixed-length digest (hash value). It is a one-way function — cannot reverse a hash to get the original message.
Key Properties
  • One-way → cannot reverse the hash to get the original data
  • Fixed-length output → regardless of how large the input is
  • Avalanche effect → tiny change in input causes a drastically different hash
  • Collision-resistant → hard to find two different inputs with the same hash
Common Hash Algorithms
AlgorithmOutput SizeStatus
MD5128 bits (16 bytes)✘ Broken for collision resistance
SHA-1160 bits✘ Deprecated / cryptographically broken
SHA-256 ✓256 bits✓ Secure — widely used
SHA-512 ✓512 bits✓ Secure — stronger than SHA-256
🧠 Encryption vs Hashing
Encryption → reversible (with correct key)  |  Hashing → one-way (irreversible by design)

Digital Signature TOP PRIORITY 🔥🔥
Provides Authentication + Integrity + Non-repudiation (NOT primarily Confidentiality)
Digital Signature provides Authentication, Integrity, and Non-repudiation.
Important: It does NOT primarily provide Confidentiality (message is not encrypted by the signature itself).
How Digital Signature Works
SIGNING: Message → Hash function → Message Digest Message Digest → Encrypt with Sender's PRIVATE KEY → Digital Signature Send (Message + Digital Signature) VERIFICATION: Received Signature → Decrypt with Sender's PUBLIC KEY → Digest 1 Received Message → Hash function → Digest 2 If Digest 1 == Digest 2 → Signature is VALID
⭐ Rule 1
Sender signs using their PRIVATE KEY
⭐ Rule 2
Receiver verifies using sender's PUBLIC KEY
⚠ Common Exam Trap
Digital Signature does NOT encrypt the message body itself — add separate encryption for confidentiality.

MAC — Message Authentication Code
Integrity + Authentication using a shared secret key — HMAC
MAC provides Integrity + Authentication using a shared secret (symmetric) key. Both parties must share the same key. Unlike digital signatures, MAC does NOT provide strong non-repudiation.
HMAC (Hash-based MAC): Message + Secret Key → HMAC function → MAC tag Sent along with message Receiver recomputes MAC and compares → verifies integrity & authenticity
MAC vs Digital Signature Comparison
PropertyMAC (HMAC)Digital Signature
Key typeSymmetric (shared secret)Asymmetric (private/public key)
Authentication✓ Yes✓ Yes
Integrity✓ Yes✓ Yes
Non-repudiation✘ Weak / No✓ Yes (strong)
SpeedFasterSlower

Key Exchange & Kerberos HIGH YIELD
Diffie-Hellman key establishment — Kerberos ticket-based authentication
Diffie-Hellman Key Exchange
Diffie-Hellman allows two parties to establish a shared secret over an insecure channel without transmitting the secret directly. It is a key exchange algorithm, NOT an encryption algorithm.
⚠ Vulnerability
Basic Diffie-Hellman is vulnerable to MITM attacks if no authentication is present. Use authenticated DH (e.g., with certificates or signatures).
Kerberos Authentication Protocol NEW
Kerberos = Network authentication protocol using tickets issued by a trusted third party called the Key Distribution Center (KDC).
Step 1: Client → Authentication Server (AS) → TGT (Ticket Granting Ticket) Step 2: Client → Ticket Granting Server (TGS) → Service Ticket Step 3: Client → Target Service (using Service Ticket) → Access Granted
  • Uses symmetric key cryptography internally
  • Default port: 88
  • Timestamps prevent replay attacks
  • Provides Single Sign-On (SSO) capability

Digital Certificate & PKI HIGH YIELD
Public Key Infrastructure — CA, RA, CRL, X.509 standard
Digital Certificate binds an Identity + Public Key, signed by a trusted Certificate Authority (CA). Follows the X.509 standard.
PKI Components
  • CA (Certificate Authority) → Trusted entity that issues and signs digital certificates
  • RA (Registration Authority) → Verifies identity before certificate issuance on behalf of CA
  • X.509 → International standard defining certificate format
  • CRL (Certificate Revocation List) → Lists certificates that have been revoked before expiry
  • OCSP → Online Certificate Status Protocol — real-time revocation check
  • Digital Certificates → Bind identity to public key, signed by CA
🧠 One-liner
Digital Certificate = Identity + Public Key + CA's Signature

IPsec — AH & ESP TOP PRIORITY 🔥🔥
Network Layer security — AH vs ESP — Transport vs Tunnel mode
IPsec operates at the Network Layer (Layer 3) and provides security services for IP communications.
ProtocolConfidentiality (Encryption)IntegrityAuthentication
AH — Authentication Header✘ NO encryption✓ Yes✓ Yes
ESP — Encapsulating Security Payload ⭐✓ Yes✓ Yes✓ Yes
IPsec Modes
👤 Transport Mode
Original IP Header | Protected Payload

Protects only the payload. Used for host-to-host communication.

🖕 Tunnel Mode ⭐
New IP Header | Entire Original IP Packet

Encapsulates the entire original packet. Used with VPNs.

⭐ Key Rules to Memorize
AH = Authentication + Integrity only (NO encryption)
ESP = Confidentiality + Integrity + Authentication (everything)
Tunnel Mode = VPNs  |  IPsec = Network Layer

IDS vs IPS TOP PRIORITY 🔥🔥
Detection vs Prevention — Signature vs Anomaly — NIDS vs HIDS
🚨 IDS — Intrusion Detection System

Detects suspicious activity → Alerts only

Traffic → IDS → Alert 🚨

Does NOT block traffic. Out-of-band / passive monitoring. Alerts administrators.

🚫 IPS — Intrusion Prevention System

Detects AND Blocks / Takes Action

Traffic → IPS → Block 🚫

Inline device — sits in traffic path and actively blocks malicious traffic.

Detection Approaches
ApproachMethodAdvantageDisadvantage
Signature-basedMatches known attack patterns/signaturesLow false positives for known attacksCannot detect new/unknown (zero-day) attacks
Anomaly-basedDetects deviation from normal behavior baselineCan detect unknown/new attacksHigher false positive rate
NIDS vs HIDS NEW
NIDS (Network-based IDS)HIDS (Host-based IDS)
Monitors network traffic at network levelMonitors activity on a single host/system
Placed at network chokepoints / segment boundariesInstalled as an agent on the machine being monitored
Broader network-wide visibilityDeep host-level visibility (files, processes, logs)
🧠 Easy Memory
IDS = Detect + Alert (passive, observes only)  |  IPS = Detect + Prevent (active, takes action)

Password Security & Salt HIGH YIELD
Secure password storage — Salting — Defense against rainbow tables
Good Password Security Practices
  • Strong passwords → long + complex + unpredictable
  • Password hashing → always store the hash, never plaintext password
  • Salting → add a random unique value before hashing each password
  • Rate limiting & account lockout → limit login attempts
  • MFA → second factor protects even if password is stolen
Salt — Why It Matters
WITHOUT Salt: Password "abc123" → Hash: d41d8cd98f00b204... (same for every user with same password) WITH Salt: User A: "abc123" + RandomSalt1 → Hash1 (unique) User B: "abc123" + RandomSalt2 → Hash2 (different!) // Salt defeats: Rainbow Tables, Precomputed Hash Attacks
🧠 Salt's Purpose
Salt ensures identical passwords produce different hashes for different users, defeating precomputed rainbow table attacks.

Zero Trust Architecture
Never trust, always verify — modern security model
Zero Trust: Do NOT automatically trust any user or device just because it is inside the corporate network perimeter. Treat every access request as potentially hostile.
⭐ Core Motto
"Never trust, always verify."
Zero Trust Principles
  • Continuous verification → authenticate and authorize every single request
  • Least privilege → grant minimum access needed for the task
  • Assume breach → design assuming attackers may already be inside
  • Strong identity & device verification → validate user + device health
  • Micro-segmentation → limit lateral movement within the network

Security Principles & Operational Concepts HIGH YIELD
Least Privilege, Defense in Depth, SIEM, Patch Management, DLP & more
🔒 Least Privilege

Give users/processes only the permissions they absolutely need — nothing more.

🏛 Defense in Depth

Use multiple layered security controls so one failure does not compromise the system.

Firewall → IDS/IPS → Auth → Encryption → Access Control
🚫 Fail-Safe Defaults

Default system state should be DENY access, unless explicitly permitted. Deny-by-default.

👥 Separation of Duties

Critical tasks divided among multiple people/roles to prevent fraud, error, and abuse of power.

ConceptWhat It Does

DLP (Data Loss Prevention)Tools and policies to prevent sensitive data from leaving the organization (exfiltration)
SIEM (Security Info & Event Mgmt)Centrally collects, correlates, and analyzes security logs/events from multiple sources for threat detection

Key Comparisons TOP PRIORITY 🔥🔥
All must-know comparison pairs — direct MCQ gold
Virus vs Worm
  • Virus → needs a host program/file to spread
  • Worm → self-replicates, spreads independently
DoS vs DDoS
  • DoS → from one/few sources
  • DDoS → from many distributed sources
Encryption vs Hashing
  • Encryption → reversible (with correct key)
  • Hashing → one-way, irreversible
Symmetric vs Asymmetric
  • Symmetric → one shared key, fast
  • Asymmetric → public/private keys, slower
IDS vs IPS
  • IDS → Detect + Alert only (passive)
  • IPS → Detect + Block/Prevent (active)
Authentication vs Authorization
  • Authentication → Who are you? (Identity)
  • Authorization → What can you do? (Permission)
AH vs ESP
  • AH → Auth + Integrity (NO encryption)
  • ESP → Confidentiality + Integrity + Auth
SSH vs Telnet
  • SSH → Encrypted, secure (Port 22)
  • Telnet → Plaintext, insecure (Port 23)
HTTP vs HTTPS
  • HTTP → No TLS, Port 80, insecure
  • HTTPS → HTTP + TLS, Port 443, secure
MAC (Auth) vs Digital Signature
  • MAC → Symmetric key, no non-repudiation
  • Digital Sig. → Asymmetric, provides non-repudiation

Business Continuity & Disaster Recovery NEW
BCP, DRP, RTO, RPO, Hot Site, Cold Site
TermMeaning
BCPBusiness Continuity Plan — keeps critical business operations running during a disruption
DRPDisaster Recovery Plan — focuses on restoring IT systems and data after a disaster
RTO ⭐Recovery Time Objective — maximum acceptable downtime (how long can we be down?)
RPO ⭐Recovery Point Objective — maximum acceptable data loss measured in time (how much data can we afford to lose?)
Hot SiteFully operational backup site — can take over almost instantly (high cost)
Cold SiteBasic backup infrastructure — needs significant setup time (lower cost)
🧠 RTO vs RPO Memory Trick
RTO = downtime tolerance — "How long can the service be DOWN?"
RPO = data-loss tolerance — "How much DATA can we afford to lose?"
