24.1 DNS Domain Hierarchy

DNS (Domain Name System - UDP/TCP Port 53) acts as the "phonebook of the Internet", translating human-friendly domain names (e.g. www.google.com) into 32-bit IPv4 or 128-bit IPv6 addresses.

DNS Hierarchical Structure

  • Root Domain (.): Top of tree, managed by 13 root server clusters globally.
  • Top-Level Domain (TLD): Generic TLDs (.com, .org, .edu) and Country-Code TLDs (.us, .uk, .in).
  • Second-Level Domain: Registered domain name (e.g. google in google.com).
  • Subdomain: Specific host service (e.g. www, mail, blog).

DNS Resolution Process (Recursive vs Iterative)

Recursive vs Iterative Queries

  • Recursive Query: Client asks Resolver to fully resolve the IP or return an error. (Resolver assumes responsibility).
  • Iterative Query: Resolver queries Root, TLD, and Authoritative servers in steps; each server returns a referral link to the next server down the chain.

24.4 DHCP DORA Process & IP Allocation

DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses, subnet masks, default gateways, and DNS servers to client devices on a local network using **UDP Ports 67 (Server) and 68 (Client)**.

The 4-Step DORA Process

  1. Discover (Client → Server): Client broadcasts DHCPDISCOVER packet (Dst MAC FF:FF:FF:FF:FF:FF) to find local DHCP servers.
  2. Offer (Server → Client): DHCP Server responds with DHCPOFFER offering an available IP address, subnet mask, and lease time.
  3. Request (Client → Server): Client broadcasts DHCPREQUEST accepting the offered IP address.
  4. Acknowledge (Server → Client): Server sends DHCPACK confirming the lease agreement. Client configures its network interface.
💡
APIPA Fallback
If no DHCP server responds to DHCPDISCOVER, Windows clients automatically assign a self-configured APIPA address (169.254.0.0/16) for local link communication.
