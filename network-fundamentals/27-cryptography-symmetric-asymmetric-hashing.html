27.1 Cryptography Terminology

  • Plaintext (P): Original readable message data.
  • Ciphertext (C): Encrypted unreadable message data.
  • Encryption (E): Process of converting Plaintext to Ciphertext using a mathematical algorithm and Key ($C = E_K(P)$).
  • Decryption (D): Process of recovering Plaintext from Ciphertext ($P = D_K(C)$).
  • Key (K): Secret numerical parameter that controls the mathematical transformation.

Section 27.2

Symmetric Encryption (Secret-Key Ciphers)

In Symmetric Encryption, the **SAME secret key** is used for both encryption and decryption.

Block Ciphers vs Stream Ciphers

  • Block Ciphers: Encrypts fixed-size blocks of plaintext (e.g. 128 bits) at a time. Examples: **AES-128 / AES-256** (Advanced Encryption Standard), DES (obsolete), 3DES, Blowfish.
  • Stream Ciphers: Encrypts plaintext bit-by-bit or byte-by-byte in a continuous stream. Examples: **ChaCha20**, RC4 (obsolete).
🔐
Section 27.3

Asymmetric Encryption (Public-Key Ciphers)

In Asymmetric Encryption, two mathematically linked keys are used: a **Public Key** (shared openly) and a **Private Key** (kept secret).

  • To send a confidential message to Alice: Encrypt using Alice's Public Key. Only Alice can decrypt it using her Private Key.
  • To digitally sign a message as Alice: Encrypt/Sign using Alice's Private Key. Anyone can verify it using Alice's Public Key.

Key Asymmetric Algorithms

  • RSA (Rivest-Shamir-Adleman): Based on the mathematical difficulty of factoring large prime numbers (uses 2048 to 4096-bit keys).
  • ECC (Elliptic Curve Cryptography): Based on algebraic structures of elliptic curves over finite fields. Offers equal security to RSA with drastically smaller key sizes (256-bit ECC key ≈ 3072-bit RSA key!).

27.4 Diffie-Hellman Key Exchange Algorithm

The Diffie-Hellman (DH / ECDHE) key exchange algorithm allows two parties to securely negotiate a shared secret symmetric key over an insecure, eavesdropped public channel without sending the key itself!

Section 27.5

Cryptographic Hash Functions & HMAC

A Cryptographic Hash Function is a one-way mathematical function that converts an arbitrary length input string into a fixed-length string of hex digits (the hash digest).

📌
Core Properties of Hash Functions
1. Deterministic: Same input always produces exact same hash.
2. One-Way (Pre-image Resistance): Impossible to reverse hash back to original plaintext.
3. Avalanche Effect: Changing 1 bit of input radically changes the output hash.
4. Collision Resistance: Computationally impossible to find two different inputs that produce the same output hash.

Common standards: SHA-256 (Secure Hash Algorithm), SHA-3, MD5 (deprecated due to collision vulnerabilities), and HMAC (Hash-based Message Authentication Code) which combines a secret key with a hash function for integrity & authenticity.
