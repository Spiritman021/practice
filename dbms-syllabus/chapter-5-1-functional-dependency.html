Functional Dependency (FD)

The foundation of Database Normalization. Master FD concepts, Armstrong's Axioms, Attribute Closure, Canonical Cover, and FD Set Equivalence — all with step-by-step examples.

💡 What is Functional Dependency?

A Functional Dependency (FD) is a constraint between two sets of attributes in a relation. It describes how one attribute (or set of attributes) uniquely determines another attribute.

FORMAL DEFINITION
X → Y (read: "X determines Y" or "Y is functionally dependent on X")
Meaning: For any two tuples t1 and t2 in relation R,
if t1[X] = t2[X] then t1[Y] = t2[Y]
🏫 Real-Life Analogy
Think of a Student Table with columns: Roll_No, Name, Age, Dept, Phone.

Roll_No → Name: If two students have the same Roll_No, they MUST have the same Name. (Roll No uniquely identifies a student's name.)
Dept → HOD: Each department has exactly one HOD, so knowing the Dept tells you the HOD.

But Name → Roll_No is NOT necessarily true (two students can share the same name).

📋 Example Table: STUDENT

Roll_NoNameDeptCityHOD
101VarunCSDelhiDr. Sharma
102RaviCSMumbaiDr. Sharma
103AmitECDelhiDr. Gupta
104PriyaCSPuneDr. Sharma
✅ FDs that HOLD in this table:
  • Roll_No → Name, Dept, City, HOD (Roll_No is a key — determines everything)
  • Dept → HOD (CS always → Dr. Sharma, EC always → Dr. Gupta)
  • {Roll_No, Dept} → HOD (also holds, since Roll_No alone already determines HOD)
❌ FDs that do NOT hold:
  • City → Name ❌ (Both 101 and 103 are from Delhi, but different names)
  • Name → Dept ❌ (Two people with same name could be in different depts)

🔀 5.1.1 — Trivial vs Non-Trivial FD

This classification is based on whether the right-hand side (Y) is a subset of the left-hand side (X).

THE 3-WAY CLASSIFICATION
Trivial FD: X → Y when Y ⊆ X
Non-Trivial FD: X → Y when Y ⊄ X
Completely Non-Trivial: X → Y when X ∩ Y = ∅
Figure 1: Three types of FDs — Trivial (Y⊆X), Non-Trivial (Y⊄X), Completely Non-Trivial (X∩Y=∅)
TypeConditionExampleAlways True?
Trivial FD Y ⊆ X {Roll_No, Name} → Roll_No ✅ Always holds
Non-Trivial FD Y ⊄ X (Y has at least one attr not in X) {Roll_No, Name} → Dept ❌ May or may not hold
Completely Non-Trivial X ∩ Y = ∅ (no common attributes) Roll_No → Name ❌ May or may not hold
💡 Key Insight for Exams
Every Trivial FD is always valid (it can never be violated). That's why it's "trivial" — it gives no useful information. In normalization, we care about non-trivial FDs because those are the ones that can create anomalies!

⚖️ 5.1.2 — Armstrong's Axioms

Armstrong's Axioms are a set of sound and complete inference rules used to derive all possible FDs from a given set of FDs. They are the foundation for computing closures and canonical covers.

📌 Sound and Complete — What does it mean?
Sound: Any FD derived using these axioms is guaranteed to be correct (no wrong FDs generated).
Complete: All valid FDs can be derived using these axioms (nothing is missed).

Axiom 1: Reflexivity (Trivial Rule)

REFLEXIVITY AXIOM
If Y ⊆ X, then X → Y
📖 Example
Given: X = {Roll_No, Name, Dept} and Y = {Roll_No, Name}
Since Y ⊆ X, we can conclude: {Roll_No, Name, Dept} → {Roll_No, Name} ✅

This always produces trivial FDs — a superset always determines any of its subsets.

Axiom 2: Augmentation (Growth Rule)

AUGMENTATION AXIOM
If X → Y, then XZ → YZ (for any attribute set Z)
📖 Example
Given: Roll_No → Dept (a student's roll number determines their department)
Then: {Roll_No, City} → {Dept, City} ✅

Intuition: If X already determines Y, adding Z to both sides doesn't break anything. X+Z still determines Y+Z, because Z determines itself (reflexivity).

Axiom 3: Transitivity (Chaining Rule)

TRANSITIVITY AXIOM
If X → Y and Y → Z, then X → Z
📖 Example
Given: Roll_No → Dept and Dept → HOD
Then: Roll_No → HOD ✅

Intuition: If Roll No gives you the Dept, and Dept gives you the HOD, then Roll No can give you the HOD directly. Like a relay chain — A passes to B, B passes to C, so A can pass to C!
Figure 2: Armstrong's Three Primary Axioms — Reflexivity, Augmentation, Transitivity

📐 Derived Rules (from the 3 Axioms)

Using the 3 primary axioms, we can derive additional useful rules:

Derived RuleFormulaDerivation IdeaExample
Union Rule If X→Y and X→Z, then X→YZ Augment first FD with Z, augment second with Y, then combine RNo→Name and RNo→Dept ⟹ RNo→{Name,Dept}
Decomposition Rule If X→YZ, then X→Y and X→Z Reflexivity: YZ→Y, then transitivity with X→YZ RNo→{Name,Dept} ⟹ RNo→Name and RNo→Dept
Pseudo-Transitivity If X→Y and WY→Z, then WX→Z Augment X→Y by W to get WX→WY, then transitivity with WY→Z A→B and CB→D ⟹ CA→D

🔒 5.1.3 — Closure of Attributes (X⁺) and FD Set (F⁺)

Part A: Attribute Closure (X⁺)

DEFINITION
Attribute Closure of X w.r.t FD set F:
X⁺ = Set of ALL attributes that can be functionally determined by X, using F

Uses: Find candidate keys, check if X→Y holds, find superkeys
🔑 Why is X⁺ important?
  • If X⁺ = all attributes of R → X is a Superkey
  • If X⁺ = all attributes AND no proper subset of X has the same closure → X is a Candidate Key
  • To check if X → Y holds: compute X⁺, check if Y ⊆ X⁺

⚙️ Algorithm: Compute Attribute Closure X⁺

Input: Attribute set X, FD set F Output: X⁺ (closure of X) Step 1: X⁺ = X // start with X itself Step 2: Repeat until no change: For each FD (A → B) in F: If A ⊆ X⁺: X⁺ = X⁺ ∪ B // add B to closure Step 3: Return X⁺

🧮 Worked Example: Compute {A, B}⁺

📋 Given
Relation R(A, B, C, D, E, F)
F = {A→B, B→C, C→D, D→E, AB→F}
Find: {A, B}⁺
1
Initialize: X⁺ = {A, B}
2
Check A→B: A ∈ X⁺? Yes → Add B. X⁺ = {A, B} (B already there, no change)
Check B→C: B ∈ X⁺? Yes → Add C. X⁺ = {A, B, C}
Check C→D: C ∈ X⁺? Yes → Add D. X⁺ = {A, B, C, D}
Check D→E: D ∈ X⁺? Yes → Add E. X⁺ = {A, B, C, D, E}
Check AB→F: {A, B} ⊆ X⁺? Yes → Add F. X⁺ = {A, B, C, D, E, F}
3
No more FDs to apply. X⁺ = {A, B, C, D, E, F} = all attributes of R
✅ Conclusion
{A, B}⁺ = {A, B, C, D, E, F} = All attributes of R.
∴ {A, B} is a Superkey. Check if it's a Candidate Key by testing subsets:
  • A⁺ = {A, B, C, D, E, F} → A alone is a Superkey too!
  ∴ A alone is a Candidate Key, and {A, B} is just a Superkey (not minimal).
Figure 3: Step-by-step computation of {A,B}⁺

Part B: Closure of FD Set (F⁺)

F⁺ (closure of FD set F) is the set of all FDs that can be derived from F using Armstrong's Axioms. It is typically very large and not computed directly — instead, we use attribute closures (X⁺) to check individual FDs.

💡 Practical Use
To check if a given FD X→Y belongs to F⁺:
Compute X⁺ using F. If Y ⊆ X⁺, then X→Y ∈ F⁺ ✅

🎯 5.1.4 — Canonical / Minimal Cover (F_c)

A Canonical Cover (also called Minimal Cover) is a simplified, equivalent version of an FD set F that contains no redundant FDs and no redundant attributes on the left-hand side.

🧹 Why do we need it?
A given FD set F may contain redundant FDs that can be derived from others. Removing them gives us the "minimal" set that is equivalent to F but cleaner — useful in normalization (3NF synthesis algorithm).
PROPERTIES OF CANONICAL COVER F_c
1. F_c is equivalent to F (i.e., F_c⁺ = F⁺) 2. No FD in F_c has a redundant LHS attribute (LHS is minimal) 3. No FD in F_c is redundant (removing any FD changes F_c⁺) 4. Each FD in F_c has exactly ONE attribute on the RHS

⚙️ Algorithm: Find Canonical Cover

Input: FD set F Output: Canonical Cover F_c Step 1: Decompose all FDs to have single attribute on RHS (use Decomposition rule: X→YZ becomes X→Y and X→Z) Step 2: Remove redundant LHS attributes For each FD A→B in F: For each attribute a in A (if A has multiple attrs): Test if (A - {a})⁺ contains B (using remaining FDs) If YES → remove 'a' from LHS (it's redundant) Step 3: Remove redundant FDs For each FD X→Y in F: Remove it temporarily: F' = F - {X→Y} Compute X⁺ using F' If Y ⊆ X⁺ → X→Y is redundant, keep it removed Else → X→Y is needed, add it back Step 4: Return remaining FDs as F_c

🧮 Worked Example: Find Canonical Cover

📋 Given
R(A, B, C)
F = {A→BC, B→C, A→B, AB→C}
Find: Canonical Cover F_c
1
Step 1: Decompose RHS to single attributes
A→BC splits into: A→B and A→C
F becomes: {A→B, A→C, B→C, A→B, AB→C}
Remove duplicate A→B: F = {A→B, A→C, B→C, AB→C}
2
Step 2: Remove redundant LHS attributes from AB→C
Test if A alone determines C (remove B from LHS of AB→C):
  A⁺ using {A→B, A→C, B→C} = {A, B, C} → C ∈ A⁺ ✅
So B is redundant in AB→C. Replace with A→C
But A→C already exists! So AB→C is now just a duplicate.
F = {A→B, A→C, B→C}
3
Step 3: Remove redundant FDs
Test A→C: Remove it temporarily. F' = {A→B, B→C}
  A⁺ using F' = {A, B, C} → C ∈ A⁺ ✅ (via A→B→C transitivity)
∴ A→C is redundant! Remove it.
F = {A→B, B→C}
4
Test A→B: F' = {B→C}. A⁺ = {A} → B ∉ A⁺ ❌. Keep A→B.
Test B→C: F' = {A→B}. B⁺ = {B} → C ∉ B⁺ ❌. Keep B→C.
✅ Final Canonical Cover
F_c = {A→B, B→C}

Verification: Using F_c, A⁺ = {A,B,C} = all attrs. This is equivalent to F (same F_c⁺ = F⁺). ✅

⚡ 5.1.5 — Equivalence of FD Sets

DEFINITION
Two FD sets F and G are equivalent if: F⁺ = G⁺ (They derive the same set of all possible FDs) Equivalently: F covers G (every FD in G can be derived from F) AND G covers F (every FD in F can be derived from G)

How to Check Equivalence?

⚙️ Algorithm: Check if F and G are Equivalent

Method: Check if F covers G AND G covers F F covers G: For each FD (X → Y) in G: Compute X⁺ using F If Y ⊆ X⁺ → ✅ (this FD is derivable from F) Else → ❌ F does NOT cover G → Not equivalent G covers F: For each FD (X → Y) in F: Compute X⁺ using G If Y ⊆ X⁺ → ✅ (this FD is derivable from G) Else → ❌ G does NOT cover F → Not equivalent If both cover each other: F ≡ G (Equivalent!)

🧮 Worked Example: Check Equivalence

📋 Given
F = {A→B, B→C, A→C}
G = {A→B, B→C}
Are F and G equivalent?
1
Check if G covers F (every FD in F derivable from G):
 • A→B: A⁺ using G = {A,B,C} → B ∈ A⁺ ✅
 • B→C: B⁺ using G = {B,C} → C ∈ B⁺ ✅
 • A→C: A⁺ using G = {A,B,C} → C ∈ A⁺ ✅
∴ G covers F ✅
2
Check if F covers G (every FD in G derivable from F):
 • A→B: A⁺ using F = {A,B,C} → B ∈ A⁺ ✅
 • B→C: B⁺ using F = {B,C} → C ∈ B⁺ ✅
∴ F covers G ✅
✅ Conclusion
Both cover each other, so F ≡ G (Equivalent)!

Notice G = {A→B, B→C} is actually the Canonical Cover of F (A→C was redundant since it's derivable from A→B and B→C via transitivity).
Figure 4: FD Set Equivalence — F and G are equivalent because F⁺ = G⁺

📋 Quick Summary — All Concepts at a Glance

ConceptDefinitionKey Use
Trivial FD
X → Y, Y⊆X		 Y is a subset of X — always holds Identifying useless FDs; exams love testing this
Non-Trivial FD
X → Y, Y⊄X		 Y has at least one attribute not in X Basis for normalization analysis
Reflexivity Y⊆X → X→Y Deriving trivial FDs; Armstrong completeness
Augmentation X→Y → XZ→YZ Adding attributes to both sides; used in closure computation
Transitivity X→Y, Y→Z → X→Z Most important axiom! Used in detecting transitive dependency (3NF)
Attribute Closure X⁺ All attrs determined by X using F Finding superkeys, candidate keys, checking FD membership
Canonical Cover F_c Minimal equivalent FD set (no redundancy) 3NF synthesis algorithm; minimal representation
FD Set Equivalence F ≡ G when F⁺ = G⁺ Comparing FD sets; verifying canonical covers

🎯 GATE & UGC-NET Exam Focus — Previous Year Questions

Q1 (GATE 2019): Which of the following FDs is trivial?
(a) A→B (b) AB→A (c) AB→C (d) A→AB
👉 Answer: (b) AB→A — Because A ⊆ {A,B}, so Y⊆X → trivial.
Q2 (GATE 2015): Given F = {A→B, BC→D, AB→C}. Compute (AB)⁺.
👉 Start: {A,B}. A→B: B∈AB✅. BC→D: need C first. AB→C: {A,B}⊆AB⁺ ✅ → add C. BC→D: {B,C}⊆{A,B,C} ✅ → add D. AB⁺ = {A,B,C,D}
Q3 (UGC-NET): Armstrong's Axioms are said to be ___.
(a) Sound only (b) Complete only (c) Sound and Complete (d) Neither
👉 Answer: (c) Sound and Complete — They generate all valid FDs and only valid FDs.
Q4 (GATE 2016): Which rule is NOT one of Armstrong's primary axioms?
(a) Reflexivity (b) Augmentation (c) Transitivity (d) Union
👉 Answer: (d) Union — Union is a derived rule, not a primary axiom.
Q5 (GATE 2020): Given F = {A→B, A→C, B→C}. What is the canonical cover?
👉 Step 1: Already single RHS. Step 2: No composite LHS. Step 3: Test A→C: Remove it, A⁺ using {A→B, B→C} = {A,B,C} → C∈A⁺ ✅ → A→C is redundant. F_c = {A→B, B→C}
Q6 (UGC-NET): If X→Y and X→Z, what can we conclude?
👉 By the Union Rule (derived from Armstrong's Axioms): X → YZ
