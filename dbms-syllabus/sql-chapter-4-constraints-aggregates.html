🔒 Part A: Constraints in SQL

A Constraint is a rule or condition applied on a table column before data can be inserted. It restricts users to enter only valid data that satisfies the defined condition, ensuring data integrity in the database.

📧
Real-Life Analogy — Gmail Account Creation

When you sign up for Gmail, you can't use a username that already exists (UNIQUE constraint). When creating a password, it must have ≥8 characters + special char + number (CHECK constraint). These are constraints — rules that enforce only valid data goes in.

📌 Where Are Constraints Applied?
Constraints are applied on columns (attributes) of a table — either at the time of CREATE TABLE or later via ALTER TABLE. Only data that satisfies the constraint is allowed into that column.

🔵 1. UNIQUE Constraint

The UNIQUE constraint ensures that all values in a column are distinct — no duplicates allowed. A table can have multiple UNIQUE constraints (unlike PRIMARY KEY which allows only one). A UNIQUE column can hold NULL values (unless also NOT NULL).

📱
Real-World Example

A mobile_number column in an employee table should be UNIQUE — no two employees can share the same mobile number. If user tries to insert a duplicate, the database will throw an error and reject the insertion.

Oracle SQL — UNIQUE
-- At CREATE TABLE time:
CREATE TABLE employees (
    emp_id       INT,
    mobile_no    VARCHAR2(15) UNIQUE,
    email        VARCHAR2(100) UNIQUE
);

-- Via ALTER TABLE (add after table exists):
ALTER TABLE employees ADD CONSTRAINT uq_mobile UNIQUE(mobile_no);

🚫 2. NOT NULL Constraint

The NOT NULL constraint ensures that a column cannot be left empty. The user must provide a value. This is the "mandatory field" rule.

⚠️ NULL ≠ Zero!
NULL means "value not available / unknown / not applicable." Zero (0) is an actual numeric value. NULL means the field is completely empty — no data was provided. NOT NULL means something must be provided.
📝
Real-World Example — Mandatory Fields in a Form

When you fill a form online, fields marked with a red asterisk (*) are mandatory — you cannot submit the form leaving them blank. That asterisk represents a NOT NULL constraint on that column in the database.

Oracle SQL — NOT NULL
CREATE TABLE students (
    student_id   INT           NOT NULL,
    name         VARCHAR2(100) NOT NULL,
    email        VARCHAR2(100)          -- Optional field, NULL allowed
);

-- This will throw an error (name cannot be NULL):
INSERT INTO students VALUES (101, NULL, 'test@mail.com');
-- ORA-01400: cannot insert NULL into ("STUDENTS"."NAME")

🔑 3. PRIMARY KEY Constraint

A PRIMARY KEY is the most important constraint in a table. It is a combination of UNIQUE + NOT NULL. Every table should have exactly one PRIMARY KEY. It uniquely identifies each row in the table.

    emp_id   INT           PRIMARY KEY,   -- UNIQUE + NOT NULL

✅ 4. CHECK Constraint

The CHECK constraint validates a custom condition (domain) before any data is inserted. If the inserted value doesn't satisfy the condition, the database rejects it with an error.

🔢
Example — Age must be > 18

Without CHECK, a user could enter age = -10 and the database would accept it (int is valid). With CHECK (age > 18), only values greater than 18 are accepted. Value 10 → Error. Value 25 → Accepted.

Oracle SQL — CHECK Constraint
CREATE TABLE employees (
    emp_id   INT            PRIMARY KEY,
    age      INT            CHECK (age > 18),
    address  VARCHAR2(50)  CHECK (address IN ('Delhi', 'Chandigarh', 'Mumbai')),
    salary   NUMBER         CHECK (salary >= 0)
);

-- age = -10 → ORA-02290: check constraint violated
-- age = 25  → ✅ Accepted
-- address = 'Pune' → ❌ Error (not in domain)
-- address = 'Delhi' → ✅ Accepted
📌 Domain = Fixed Set of Valid Values
When you use CHECK with IN ('value1', 'value2', ...), you are fixing the domain of the column — restricting it to only a predefined set of valid values.

🔗 5. FOREIGN KEY Constraint ⭐⭐⭐

A FOREIGN KEY is used for Referential Integrity. It links one table to another — specifically to the PRIMARY KEY of another table (or itself). It ensures that values in one table always reference valid values in another table.

⭐⭐⭐ Very Important Topic
FOREIGN KEY is one of the most important topics in DBMS — it covers Referential Integrity, cascading operations (ON DELETE CASCADE, ON UPDATE), and parent-child table relationships. It is covered in-depth in a dedicated video (and upcoming SQL chapter).
Oracle SQL — FOREIGN KEY (Overview)
-- Parent table (referenced table)
CREATE TABLE departments (
    dept_id   INT           PRIMARY KEY,
    dept_name VARCHAR2(50)
);

-- Child table (table with the foreign key)
CREATE TABLE employees (
    emp_id  INT  PRIMARY KEY,
    name    VARCHAR2(100),
    dept_id INT  REFERENCES departments(dept_id)  -- Foreign Key
);

-- A dept_id of 99 cannot be inserted in employees
-- if 99 does not exist in the departments table.
-- This is Referential Integrity.

🎛️ 6. DEFAULT Constraint

The DEFAULT constraint automatically assigns a preset value to a column when no value is explicitly provided during insert. The column will never be empty — it takes the default value.

⌚
Analogy — Watch Default Time

A newly manufactured watch always shows 10:10 as the default time in the store. Once you buy and set it, the actual time is used. DEFAULT in SQL works the same way — the preset value is used until a real value is provided.

Oracle SQL — DEFAULT
CREATE TABLE employees (
    emp_id   INT            PRIMARY KEY,
    name     VARCHAR2(100) NOT NULL,
    salary   NUMBER         DEFAULT 10000,      -- If not provided → 10000
    status   VARCHAR2(20)  DEFAULT 'active',   -- If not provided → 'active'
    join_date DATE          DEFAULT SYSDATE     -- Auto-set to today's date
);

-- Insert without salary → salary will be 10000 automatically
INSERT INTO employees(emp_id, name) VALUES (101, 'Rahul');
-- Result: salary = 10000, status = 'active', join_date = today

🔀 All 6 Constraints Together in One Table

Oracle SQL — Complete Example
CREATE TABLE employee (
    emp_id    INT            PRIMARY KEY,              -- Unique + NOT NULL
    name      VARCHAR2(100) NOT NULL,                  -- Mandatory field
    email     VARCHAR2(150) UNIQUE,                     -- No duplicate emails
    age       INT            CHECK (age > 18),          -- Must be > 18
    dept_id   INT            REFERENCES dept(dept_id), -- Foreign Key
    salary    NUMBER         DEFAULT 10000              -- Defaults to 10000
);

📊 Part B: Aggregate Functions in SQL

Aggregate functions operate on a set of rows and return a single summary value. There are exactly 5 aggregate functions in SQL. They are heavily used in GROUP BY queries, subqueries, and correlated queries.

⬆️
MAX()
Returns the maximum value in the column
⬇️
MIN()
Returns the minimum value in the column
🔢
COUNT()
Returns the number of rows (or non-NULL values)
➕
SUM()
Returns the total sum of all values in the column
📐
AVG()
Returns the average = SUM/COUNT (ignoring NULLs)

📌 Key Rule: NULL is Ignored by All Aggregate Functions
NULL means "value not available." All 5 aggregate functions (MAX, MIN, COUNT, SUM, AVG) automatically skip NULL values in their calculations. Only COUNT(*) counts NULLs because it counts rows, not values.

⬆️ 1. MAX() — Maximum Value

SQL — MAX
SELECT MAX(salary) FROM emp;
-- Ignores NULL row. Checks: 10000, 20000, 30000, 30000, 50000
-- Maximum = 50000
Output
50000

⬇️ 2. MIN() — Minimum Value

SQL — MIN
SELECT MIN(salary) FROM emp;
-- Ignores NULL row. Checks: 10000, 20000, 30000, 30000, 50000
-- Minimum = 10000
Output
10000

🔢 3. COUNT() — Three Variations

SQL — COUNT Variations
-- Variation 1: COUNT(*) → counts ALL rows including NULL rows
SELECT COUNT(*) FROM emp;
-- 6 total rows → Output: 6

-- Variation 2: COUNT(column) → counts non-NULL values only
SELECT COUNT(salary) FROM emp;
-- Skips NULL row → counts: 10000, 20000, 30000, 30000, 50000 = 5
-- Output: 5

-- Variation 3: COUNT(DISTINCT column) → counts unique non-NULL values
SELECT COUNT(DISTINCT salary) FROM emp;
-- Unique values: 10000, 20000, 30000, 50000 (30000 counted once)
-- NULL skipped → Output: 4
QueryWhat is CountedOutput
COUNT(*)All rows including NULL rows6
COUNT(salary)Non-NULL salary values only5
COUNT(DISTINCT salary)Unique non-NULL salary values4

➕ 4. SUM() — Total Sum

SQL — SUM Variations
-- SUM(salary) → adds all non-NULL values
SELECT SUM(salary) FROM emp;
-- 10000 + 20000 + 30000 + 30000 + 50000 = 1,40,000
-- Output: 1,40,000

-- SUM(DISTINCT salary) → adds unique values only, 30000 counted once
SELECT SUM(DISTINCT salary) FROM emp;
-- 10000 + 20000 + 30000 + 50000 = 1,10,000 (30000 counted once)
-- Output: 1,10,000
QueryCalculationOutput
SUM(salary)10K + 20K + 30K + 30K + 50K1,40,000
SUM(DISTINCT salary)10K + 20K + 30K + 50K (30K once)1,10,000

📐 5. AVG() — Average Value

Formula of Average
AVG(salary) = SUM(salary) / COUNT(salary)
SQL — AVG Variations
-- AVG(salary) → SUM(salary) / COUNT(salary)
SELECT AVG(salary) FROM emp;
-- SUM = 1,40,000 | COUNT (non-NULL) = 5
-- AVG = 1,40,000 / 5 = 28,000
-- Output: 28,000

-- AVG(DISTINCT salary) → SUM(DISTINCT) / COUNT(DISTINCT)
SELECT AVG(DISTINCT salary) FROM emp;
-- SUM(DISTINCT) = 1,10,000 | COUNT(DISTINCT) = 4
-- AVG = 1,10,000 / 4 = 27,500
-- Output: 27,500

🎯 Exam Focus — Key Q&A

Q1: What is the difference between UNIQUE and PRIMARY KEY?
👉 Both disallow duplicates. But PRIMARY KEY = UNIQUE + NOT NULL. A table can have multiple UNIQUE constraints but only ONE PRIMARY KEY.

Q2: What is NULL in SQL?
👉 NULL means the value is unknown or not available — it is NOT zero or empty string. All aggregate functions (MAX, MIN, COUNT(col), SUM, AVG) ignore NULL values. Only COUNT(*) counts NULL rows.

Q3: What constraint prevents entering -10 as age?
👉 CHECK constraint: CHECK (age > 0) or CHECK (age >= 18).

Q4: What is the output of COUNT(*) vs COUNT(salary) if one row has NULL salary?
👉 COUNT(*) counts all rows including the NULL row. COUNT(salary) skips the NULL row and counts only rows with a salary value.

Q5: How is AVG(salary) computed internally?
👉 AVG(salary) = SUM(salary) / COUNT(salary). Both SUM and COUNT skip NULLs.

Q6: What does AVG(DISTINCT salary) compute?
👉 It uses SUM(DISTINCT salary) / COUNT(DISTINCT salary). Duplicate values are counted only once in both sum and count.

Q7: What is the purpose of FOREIGN KEY?
👉 FOREIGN KEY enforces Referential Integrity — it ensures that values in one table's column correspond to valid values in another (parent) table's PRIMARY KEY.

Q8: What does DEFAULT constraint do?
👉 It automatically assigns a preset value to a column when no value is provided during INSERT. The column will never be NULL if DEFAULT is set.

Q9: What is the key difference between CHECK and NOT NULL?
👉 NOT NULL only checks whether a value is provided. CHECK validates if the provided value satisfies a specific condition/domain.

Q10: SELECT COUNT(DISTINCT salary) from a table with values {10000, 20000, 30000, 30000, 50000, NULL}?
👉 NULL is skipped. Unique non-NULL values: {10000, 20000, 30000, 50000} → Output: 4
