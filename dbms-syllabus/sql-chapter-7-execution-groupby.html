⚙️ Part A: Order of SQL Query Execution

When you write a SQL query, you write it in this order: SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY. But the database engine executes it in a completely different order! Understanding this is key to writing correct queries and cracking interviews.

🧠 The Critical Insight
You write: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
Engine runs: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

SELECT is written first but runs 6th! That is why you cannot use a SELECT alias in a WHERE clause — WHERE runs before SELECT.

🔬 Step-by-Step Execution Trace

1
FROM employee
The entire employee table is loaded into memory. This is always step 1 — the engine must know which table(s) to work with before doing anything else. All 6 rows are available.
→ All 6 rows loaded: Ram, Amrit, Ravi, Nitin, Varun, Priya
2
JOIN (if used)
If multiple tables are joined (JOIN … ON … or comma-separated tables), the join operation runs here — combining rows from multiple tables based on the join condition. Not used in this example.
→ Skipped (single table query)
3
WHERE city = 'Delhi'
Filter rows at the individual tuple level. Each row is checked against the condition. Rows not matching are rejected. WHERE runs before grouping — so it filters individual rows, not groups.
→ Nitin (Mumbai) ❌ rejected. Remaining: Ram, Amrit, Ravi, Varun, Priya (5 rows)
4
GROUP BY department
Groups all remaining rows by the specified column. Rows with the same department value are combined into one group. After this step, you no longer see individual rows — you see groups.
→ HR group: {Ram, Ravi} · Marketing group: {Amrit, Priya} · IT group: {Varun}
5
HAVING COUNT(department) < 5
Filters groups (not rows). This is the WHERE clause for groups. Aggregate functions like COUNT, SUM, AVG can be used here. Groups not satisfying the condition are rejected.
→ HR count=2 ✅ · Marketing count=2 ✅ · IT count=1 ✅ → All 3 groups pass (all < 5)
6
SELECT department, COUNT(department)
Now — and only now — does SELECT run. It picks which columns/expressions to include in the final result set. Despite being written first in the query, it runs 6th. This is why aliases defined in SELECT can't be used in WHERE or HAVING.
→ Output: (HR, 2), (Marketing, 2), (IT, 1)
7
DISTINCT (if used)
If SELECT DISTINCT was used, duplicate rows are removed from the result set at this stage. Not used in this example.
→ Skipped (no DISTINCT in this query)
8
ORDER BY COUNT(department) DESC
Sort the result set. Descending means highest count first. The data is all selected already — ORDER BY just rearranges for presentation.
→ Marketing(2), HR(2), IT(1) — sorted high→low
9
LIMIT 1
Clips the result to the top N rows. Runs last — after everything is selected, filtered, grouped, and sorted. This gives you the "top 1 department with most employees."
→ Final output: Marketing · 2 (the department with highest employee count in Delhi)

⚠️ Common Mistake: WHERE vs HAVING
WHERE filters individual rows (runs at step 3, before grouping). You cannot use aggregate functions in WHERE.
HAVING filters groups (runs at step 5, after grouping). You must use aggregate functions in HAVING.

❌ Wrong: WHERE COUNT(dept) > 2 — COUNT not allowed in WHERE
✅ Right: HAVING COUNT(dept) > 2 — use HAVING for group-level conditions

📊 Part B: GROUP BY Clause

GROUP BY is used to arrange rows with the same value in a column into groups so that aggregate functions (COUNT, SUM, AVG, MAX, MIN) can be applied per group. It is the fundamental tool for all "department-wise", "branch-wise", "city-wise" summary queries.

📌 Classic Use Case
Problem: Find the number of employees in each department.
Problem: Find the total salary department-wise.
Problem: Find how many students are in each branch of a university.

All of these require GROUP BY — because you need to split data into groups, then apply an aggregate function on each group.

⚠️ The Two Critical Rules of GROUP BY

R1
Only the GROUP BY column can appear in SELECT directly.
If you write GROUP BY department, only department can be listed alone in SELECT. You cannot directly write name, eid, or city — those are individual-row values, not group-level values.
R2
Any other column must be wrapped in an aggregate function.
If you want to show any other attribute in SELECT, wrap it: COUNT(eid), SUM(salary), MAX(salary) etc. The aggregate collapses all rows in the group to a single value.
⚠️ Why These Rules Exist
After GROUP BY, you no longer have individual rows — you have groups. A group for HR has 2 employees. If you ask "what is the name of the HR group?", there's no single answer — it could be Ram or Ravi. That's why you must either use the GROUP BY column (which has one value per group) or use an aggregate function to collapse multiple values into one.

📝 SQL Queries — GROUP BY Examples

Oracle SQL — GROUP BY
-- Q1: Count employees in each department
SELECT   department, COUNT(*) AS num_employees
FROM     employee
GROUP BY department;
-- Output: HR→2, Marketing→3, IT→1

-- Q2: Total salary per department (assumes salary column exists)
SELECT   department, SUM(salary) AS total_salary
FROM     employee
GROUP BY department;

-- Q3: Average salary per department
SELECT   department, AVG(salary) AS avg_salary
FROM     employee
GROUP BY department;

-- Q4: Departments where more than 1 employee works (HAVING filter)
SELECT   department, COUNT(*) AS num_employees
FROM     employee
GROUP BY department
HAVING   COUNT(*) > 1;
-- Output: HR→2, Marketing→3 (IT excluded, only 1 employee)

-- Q5: Delhi employees only, count per department (WHERE + GROUP BY)
SELECT   department, COUNT(*) AS delhi_count
FROM     employee
WHERE    city = 'Delhi'
GROUP BY department;
-- Nitin (Mumbai) excluded by WHERE first, then grouped
-- Output: HR→2, Marketing→2 (Amrit+Priya), IT→1

❌ Common Errors with GROUP BY

Common Errors
-- ❌ ERROR: Cannot select 'name' directly when using GROUP BY department
-- ORA-00979: not a GROUP BY expression
SELECT   department, name, COUNT(*)
FROM     employee
GROUP BY department;   -- ❌ 'name' is not in GROUP BY

-- ✅ FIX: Either add name to GROUP BY, or wrap in aggregate
SELECT   department, MAX(name), COUNT(*)   -- MAX(name) is an aggregate
FROM     employee
GROUP BY department;

-- ❌ ERROR: Cannot use aggregate in WHERE
SELECT   department
FROM     employee
WHERE    COUNT(*) > 2;   -- ❌ WHERE runs before grouping!

-- ✅ FIX: Use HAVING for group-level conditions
SELECT   department
FROM     employee
GROUP BY department
HAVING   COUNT(*) > 2;   -- ✅

🎯 Interview & Exam — Key Q&A

Q1: In what order does SQL execute a query?
👉 FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. SELECT is written first but executes 6th.

Q2: Why can't you use a SELECT alias in a WHERE clause?
👉 Because WHERE runs at step 3, before SELECT runs at step 6. The alias doesn't exist yet when WHERE is processed.

Q3: What is the difference between WHERE and HAVING?
👉 WHERE filters individual rows before grouping (step 3) and cannot use aggregate functions. HAVING filters groups after GROUP BY (step 5) and must use aggregate functions.

Q4: What is GROUP BY used for?
👉 GROUP BY groups rows that have the same value in a column so that aggregate functions (COUNT, SUM, AVG, MAX, MIN) can be applied per group — enabling department-wise, city-wise, branch-wise summaries.

Q5: What columns can appear in SELECT when using GROUP BY?
👉 Only (1) the column(s) listed in GROUP BY, or (2) any other column wrapped in an aggregate function. Directly using a non-grouped column in SELECT is an error.

Q6: Write a query to find which departments have more than 2 employees.
👉 SELECT department, COUNT(*) FROM employee GROUP BY department HAVING COUNT(*) > 2;

Q7: Why does ORDER BY run so late (step 8)?
👉 Because ORDER BY only sorts the final result for display. All filtering, grouping, and selection must happen first — you can't sort data that hasn't been selected yet.

Q8: Can you use WHERE and HAVING together?
👉 Yes! WHERE filters rows first (e.g., WHERE city='Delhi'), then GROUP BY groups what's left, then HAVING filters those groups (e.g., HAVING COUNT(*) > 1).

Q9: What does LIMIT do and when does it run?
👉 LIMIT restricts the output to top N rows. It runs last (step 9) — after all filtering, grouping, selection, and sorting. It's the final "clip" of the output.

Q10: What is the output of: SELECT department, COUNT(*) FROM employee GROUP BY department; on the given EMP table?
👉 HR → 2, Marketing → 3, IT → 1 (order may vary depending on engine).
