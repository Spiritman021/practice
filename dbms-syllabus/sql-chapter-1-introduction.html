💡 1. What is SQL?

SQL stands for Structured Query Language. It is the standard language for communication between a User and a Relational Database that stores structured (table-based) data.

🗣️ Analogy: Language for Communication
Just as humans use Hindi or English to communicate with each other, a user uses SQL to communicate with a database. SQL is the bridge between the user (who wants data) and the database (which holds the data).
SQL — Communication Bridge Between User and Database

🗂️ Why "Structured"?

The word "Structured" refers to the data model: data is always stored in fixed, predefined Tables (also called Relations). Because the structure (schema) must be created before inserting data, we call this structured data. That is also why this subject is often called RDBMS — Relational Database Management System.

📌 SQL = Structured Query Language 📌 Structured = Data in Tables 📌 Table = Relation 📌 Subject = RDBMS

🏛️ 2. History & Evolution of SQL

The evolution of SQL spans over 50 years and is a regularly tested topic in competitive exams.

1970
Dr. E.F. Codd (IBM) — "Father of DBMS" — published his landmark paper on the Relational Model, proposing storage of data in tables (relations) and retrieval via mathematical operations.
Early 1970s
E.F. Codd proved his model using two mathematical tools:
  • Relational Algebra — Procedural: SELECT (σ), PROJECT (π), JOIN (⋈)
  • Tuple Relational Calculus — Declarative: describes what to retrieve
Mid 1970s
IBM implemented the relational model as a real query language, initially named SEQUEL — Simple English Query Language.
Late 1970s
SEQUEL was shortened to SQL (Structured Query Language). All keywords — SELECT, FROM, WHERE, GROUP BY, JOIN — are based on natural English words, making SQL human-readable.
1980s – 1990s
Major commercial RDBMS products emerged: Oracle (dominant), IBM DB2, Microsoft SQL Server, and open-source MySQL.
Today
Only ~10% of data on Earth is structured. The remaining ~90% is unstructured (images, video, text) handled by NoSQL systems (MongoDB, Cassandra, Spark). But SQL remains the essential foundation every developer must master first.

⚙️ 3. Key Features of SQL

🔹 Feature 1: Domain-Specific Language (DSL)

TypeDefinitionExamples
General-Purpose Language (GPL)Can be used across many different domainsC, C++, Java, Python
Domain-Specific Language (DSL)Designed for and restricted to one specific domain onlySQL, HTML, MATLAB, LaTeX
🎯 Why SQL is a DSL
SQL can only be used with Relational Databases where data is in tables. You cannot build a mobile UI or an OS with SQL. Its domain is strictly: query and manipulate structured/tabular data inside RDBMS.

🔹 Feature 2: Declarative Language

ParadigmWhat You Must SpecifyExamples
ProceduralWHAT to do + HOW to do it (step-by-step logic)C, C++, PL/SQL
DeclarativeOnly WHAT to do — the DBMS handles HOW internallySQL, HTML, CSS
SQL — Declarative
-- State WHAT you want. The DBMS figures out HOW internally.
SELECT name, address
FROM   students
WHERE  address = 'Delhi';
-- No loops, no file reading, no algorithm needed from the user.
C — Procedural (Equivalent)
// Must specify every step of HOW to scan records manually
for (int i = 0; i < total; i++) {
    if (strcmp(s[i].address, "Delhi") == 0)
        printf("%s %s\n", s[i].name, s[i].address);
}
⚠️ PL/SQL is Procedural — Not Pure SQL
PL/SQL adds procedures, functions, triggers, cursors to SQL. Pure SQL = Declarative. PL/SQL = Procedural add-on.

🏗️ 4.1 DDL — Data Definition Language

DDL commands deal with the schema (structure) — they define, modify, or remove the table structure itself, not the data inside it.

CommandPurposeExample
CREATECreates a new table, database, view, or indexCREATE TABLE students (...)
ALTERModifies existing table structure (add/drop/modify column)ALTER TABLE students ADD email VARCHAR(50)
DROPPermanently removes table structure and all its dataDROP TABLE students
TRUNCATERemoves all rows but keeps the structure intactTRUNCATE TABLE students
RENAMERenames an existing tableRENAME TABLE students TO learners
SQL — DDL
-- CREATE: Define the schema
CREATE TABLE students (
    student_id  INT           PRIMARY KEY,
    name        VARCHAR2(100) NOT NULL,
    address     VARCHAR2(200),
    age         INT           CHECK (age > 0)
);

-- ALTER: Add a column
ALTER TABLE students ADD email VARCHAR2(150);

-- TRUNCATE: Remove all rows, keep structure
TRUNCATE TABLE students;

-- DROP: Remove everything — irreversible!
DROP TABLE students;

✏️ 4.2 DML — Data Manipulation Language

CommandPurposeExample
SELECTRetrieves / fetches rows from table(s)SELECT * FROM students
INSERTAdds new rows into the tableINSERT INTO students VALUES (...)
UPDATEModifies existing data valuesUPDATE students SET age=21 WHERE id=5
DELETERemoves specific rows (supports WHERE)DELETE FROM students WHERE id=5
SQL — DML
INSERT INTO students (student_id,name,address,age)
VALUES (101, 'Rahul Sharma', 'Delhi', 20);

SELECT name, address FROM students WHERE address = 'Delhi';

UPDATE students SET age = 21 WHERE student_id = 101;

DELETE FROM students WHERE student_id = 101;
⚠️ Classic Exam Trap — TRUNCATE vs DELETE
  • TRUNCATE → DDL. Cannot rollback. Removes ALL rows. Resets auto-increment. Faster.
  • DELETE → DML. Can rollback. Supports WHERE. Row-by-row deletion. Slower.

🔐 4.3 DCL — Data Control Language

CommandPurposeExample
GRANTGives specific privileges to a userGRANT SELECT ON students TO john
REVOKETakes back previously granted privilegesREVOKE SELECT ON students FROM john
SQL — DCL
GRANT  SELECT, INSERT ON students TO 'employee_john';
REVOKE SELECT, INSERT ON students FROM 'employee_john';

🔄 4.4 TCL — Transaction Control Language

CommandPurposeAnalogy
COMMITPermanently saves all changes in the current transaction✅ "Confirm Payment"
ROLLBACKUndoes all changes back to the last COMMIT↩️ Cancelling a failed transfer
SAVEPOINTCreates a named checkpoint within a transaction💾 Download checkpoint at 50%
SQL — TCL (Bank Transfer)
BEGIN TRANSACTION;
UPDATE accounts SET balance=balance-5000 WHERE account_id='ACC_A';
SAVEPOINT sp_debit;
UPDATE accounts SET balance=balance+5000 WHERE account_id='ACC_B';
COMMIT;           -- both steps OK → save permanently
-- ROLLBACK;      -- if anything fails → undo everything

🔑 5. Constraints in SQL

Constraints are rules enforced on columns to maintain data accuracy and integrity. Applied during DDL, validated during DML.

ConstraintPurposeKey Rule
PRIMARY KEYUniquely identifies each rowUnique + NOT NULL. Only one per table.
FOREIGN KEYLinks to another table's primary keyEnsures Referential Integrity
UNIQUEAll values in column must be distinctCAN be NULL (unlike PK). Multiple per table.
NOT NULLColumn cannot store NULLMandatory field
CHECKValidates a custom conditione.g., age > 0, marks <= 100
DEFAULTAuto-fills a default value when none is providede.g., status DEFAULT 'active'
SQL — Constraints
CREATE TABLE employees (
    emp_id   INT            PRIMARY KEY,
    name     VARCHAR2(100) NOT NULL,
    email    VARCHAR2(150) UNIQUE,
    age      INT            CHECK (age >= 18),
    dept_id  INT            REFERENCES departments(dept_id),
    status   VARCHAR2(20)  DEFAULT 'active'
);

🔢 6. Operators, Clauses & Aggregate Functions

⚙️ Important Operators

OperatorDescriptionExample
LIKEPattern matching. %=any string, _=one charWHERE name LIKE 'Ra%'
BETWEENRange check (inclusive on both ends)WHERE age BETWEEN 18 AND 25
INValue matches any item in a listWHERE city IN ('Delhi','Mumbai')
NOT INValue matches none in the listWHERE city NOT IN ('Delhi')

📊 Key Clauses

ClausePurposePosition
WHEREFilters rows before groupingAfter FROM
GROUP BYGroups rows for aggregationAfter WHERE
HAVINGFilters groups (WHERE cannot use aggregates)After GROUP BY
ORDER BYSorts result ASC/DESCNear end
DISTINCTRemoves duplicate rowsAfter SELECT

📈 Aggregate Functions

COUNT()SUM() AVG()MAX()MIN()
SQL — All Clauses Together
SELECT   department, COUNT(emp_id) AS total, AVG(salary) AS avg_sal
FROM     employees
WHERE    status = 'active'
GROUP BY department
HAVING   AVG(salary) > 50000
ORDER BY avg_sal DESC;
-- Logical Execution Order:
-- FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

🔗 7. Joins & Nested Queries (Highest Priority)

⭐⭐⭐ Most Important SQL Topic — GATE + Placements + IBPS SO
Joins and Subqueries are the most tested SQL topic in both competitive exams and placement interviews. Master this chapter — it is non-negotiable.
Join TypeReturnsPriority
INNER JOINOnly matching rows from both tables⭐⭐⭐ Critical
LEFT OUTER JOINAll left rows + matched right (NULL if no match)⭐⭐⭐ Critical
RIGHT OUTER JOINAll right rows + matched left (NULL if no match)⭐⭐ High
FULL OUTER JOINAll rows from both tables (NULL where no match)⭐⭐ High
CROSS JOINCartesian product (every row × every row)⭐ Medium
SELF JOINTable joined with itself (e.g., employee–manager)⭐⭐ High
SQL — Joins
-- INNER JOIN: students with their department names
SELECT s.name, d.dept_name
FROM   students s
INNER JOIN departments d ON s.dept_id = d.dept_id;

-- LEFT JOIN: All students, even those without a dept
SELECT s.name, d.dept_name
FROM   students s
LEFT JOIN departments d ON s.dept_id = d.dept_id;

-- Correlated Subquery: employees above dept average salary
SELECT e1.name, e1.salary
FROM   employees e1
WHERE  e1.salary > (SELECT AVG(e2.salary)
                    FROM employees e2
                    WHERE e2.dept_id = e1.dept_id);

🎯 Exam Focus — Key Q&A

Q1: Who is the Father of DBMS and when?
👉 Dr. E.F. Codd (IBM), 1970, published paper on the Relational Model.

Q2: What was SQL originally called?
👉 SEQUEL — Simple English Query Language.

Q3: SQL is classified as which two types of language?
👉 Domain-Specific Language (only RDBMS) + Declarative Language (WHAT, not HOW).

Q4: TRUNCATE vs DELETE difference?
👉 TRUNCATE = DDL, no rollback, removes all rows, resets auto-increment. DELETE = DML, supports rollback & WHERE clause.

Q5: Correct SQL execution order?
👉 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

Q6: Can PRIMARY KEY have NULL values?
👉 No. PRIMARY KEY = Unique + NOT NULL. UNIQUE key can have one NULL.

Q7: Difference between WHERE and HAVING?
👉 WHERE filters rows before grouping. HAVING filters groups after GROUP BY. Aggregate functions cannot go in WHERE.

Q8: Which DCL command removes privileges?
👉 REVOKE.
