⚖️ Part 1: ALTER vs UPDATE

These two commands are the most commonly confused in SQL. The key to understanding them lies in one simple rule: ALTER operates on structure. UPDATE operates on data.

🧠 Mental Model — The Golden Rule
Think of a table as a spreadsheet:
  • ALTER changes the column headers (structure/schema) — adds/removes/renames columns, changes data types
  • UPDATE changes the cell values (data) — modifies values in existing rows
Structure (Schema) vs Data — What Each Command Touches

🏗️ ALTER

CategoryDDL (Data Definition Language)
AffectsTable structure / schema only
ChangesColumn names, data types, sizes, table name, constraints
Data?Does NOT change any data values
Rollback?No (DDL commits automatically in Oracle)

✏️ UPDATE

CategoryDML (Data Manipulation Language)
AffectsTable data (cell values) only
ChangesValues inside rows — salary, name, id, etc.
Schema?Does NOT change any schema/structure
Rollback?Yes — can ROLLBACK before COMMIT

📝 ALTER — What It Can Do (Structure Changes)

OperationExample
Add a new columnALTER TABLE employee ADD email VARCHAR2(100);
Remove an existing columnALTER TABLE employee DROP COLUMN email;
Change column data typeALTER TABLE employee MODIFY id VARCHAR2(10);
Change column sizeALTER TABLE employee MODIFY name VARCHAR2(50);
Rename a columnALTER TABLE employee RENAME COLUMN id TO emp_id;
Rename the tableALTER TABLE employee RENAME TO emp_detail;

📝 UPDATE — Syntax & Examples (Data Changes)

Oracle SQL — UPDATE
-- Syntax:
UPDATE table_name
SET    column_name = new_value
[WHERE condition];

-- Example 1: Double ALL employees' salaries (no WHERE = affects all rows)
UPDATE employee
SET    salary = salary * 2;

-- Example 2: Double salary of ONLY employee with id = 1 (WHERE = specific row)
UPDATE employee
SET    salary = salary * 2
WHERE  id = 1;

-- Example 3: Update multiple columns at once
UPDATE employee
SET    salary = 50000, name = 'Rahul'
WHERE  id = 2;
⚠️ UPDATE without WHERE = Danger!
If you run UPDATE employee SET salary = 0; without a WHERE clause, all rows in the table will be updated. Always double-check your WHERE condition before running UPDATE in production.

🗑️ Part 2: DELETE vs DROP vs TRUNCATE

These three commands all "remove" something from the database — but what they remove and how they do it are very different.

✏️
DELETE
DML Command
Removes specific rows (with WHERE) or all rows (without WHERE)

✅ Rollback possible
✅ WHERE clause supported
⚠️ Slower (row-by-row + log)
💥
DROP
DDL Command
Removes the entire table — structure AND data, permanently

❌ No rollback
❌ No WHERE clause
❌ Table ceases to exist
⚡
TRUNCATE
DDL Command
Removes ALL rows but keeps the table structure intact

❌ No rollback
❌ No WHERE clause
✅ Faster (table-level lock)

🔍 Deep Dive — DELETE

DELETE is a DML command that removes one or more rows from a table. It supports a WHERE clause for selective deletion and creates a transaction log, enabling rollback.

Oracle SQL — DELETE
-- Delete ALL rows (table structure remains)
DELETE FROM student;
-- Output: 3 rows deleted.

-- Delete a specific row (using WHERE)
DELETE FROM student
WHERE id = 1;
-- Output: 1 row deleted.

-- After deleting, you can ROLLBACK (before COMMIT)
ROLLBACK;   -- Restores deleted rows from the transaction log

-- To permanently save the deletion:
COMMIT;

🔍 Deep Dive — DROP

DROP TABLE is a DDL command that permanently removes the entire table — both the structure and all data inside it. After DROP, the table no longer exists. No rollback is possible.

Oracle SQL — DROP TABLE
DROP TABLE student;
-- Output: Table dropped.

-- After DROP, the table is gone:
DESC student;
-- Error: ORA-04043: object student does not exist
☠️ DROP is the Most Dangerous DDL Command
DROP permanently removes the table and all its data. There is NO built-in rollback. This is why DROP access is typically restricted to the DBA (Database Administrator) only. Data is the most valuable asset of any organization.

🔍 Deep Dive — TRUNCATE

TRUNCATE is a DDL command that deletes all rows from a table instantly, using a table-level lock. The table structure (schema) remains intact and can be reused. No rollback is possible, and no WHERE clause is supported.

Oracle SQL — TRUNCATE
TRUNCATE TABLE student;
-- Output: Table truncated.

-- After TRUNCATE, table structure still exists:
DESC student;
-- Output: Id (NUMBER), Name (VARCHAR2) — columns shown, no rows

-- ROLLBACK after TRUNCATE? NO — it's DDL, no log created

⭐ The Recycle Bin Analogy — Remember This!
  • DELETE = Moving files to the Recycle Bin. You can restore (ROLLBACK) anytime before emptying.
  • TRUNCATE = Shift+Delete on all files. Instantly gone, no recycle bin, no recovery.
  • DROP = Deleting the entire folder (not just the files). The container itself is destroyed.

🔍 Why is DELETE Slower than TRUNCATE?

📖 Internal Mechanism Explanation
  • DELETE: Applies a row-level lock → deletes rows one by one → writes each deleted row to a transaction log (so ROLLBACK is possible) → then removes from table. More steps = slower.
  • TRUNCATE: Applies a table-level lock → deallocates the entire data pages in one operation → no row-by-row log written. Fewer steps = dramatically faster on large tables.
Oracle SQL — DELETE with WHERE (Selective Deletion)
-- Student table: Id=1 (A), Id=2 (B), Id=3 (C)

-- Delete only student with Id=1 (A remains untouched: B and C)
DELETE FROM student
WHERE id = 1;

-- Check what remains:
SELECT * FROM student;
-- Result: 2 | B | ... and 3 | C | ... (row 1 deleted)

-- TRUNCATE has no WHERE — deletes EVERYTHING:
TRUNCATE TABLE student;   -- All rows gone, cannot add WHERE

🎯 Exam Focus — Key Q&A

Q1: What is the fundamental difference between ALTER and UPDATE?
👉 ALTER changes the table structure (schema) — DDL. UPDATE changes data values inside rows — DML.

Q2: Which three commands are DDL and which is DML among DELETE, DROP, TRUNCATE?
👉 DROP and TRUNCATE are DDL. DELETE is DML.

Q3: After TRUNCATE, can you ROLLBACK?
👉 No. TRUNCATE is a DDL command — it does not write a transaction log, so rollback is not possible.

Q4: After DELETE (without COMMIT), can you ROLLBACK?
👉 Yes. DELETE is DML and writes a transaction log. You can ROLLBACK before COMMIT to restore the deleted rows.

Q5: What is the difference between TRUNCATE and DROP?
👉 TRUNCATE removes all rows but keeps the table structure. DROP removes both the rows and the table structure permanently.

Q6: Why is TRUNCATE faster than DELETE?
👉 TRUNCATE uses a table-level lock and deallocates data pages in one go without writing row-level logs. DELETE deletes row-by-row and logs each deletion for rollback support, making it slower.

Q7: Can you use WHERE with TRUNCATE?
👉 No. TRUNCATE always removes ALL rows. For selective row deletion, use DELETE with a WHERE clause.

Q8: What is the computer analogy for DELETE vs TRUNCATE?
👉 DELETE = Moving files to Recycle Bin (recoverable). TRUNCATE = Shift+Delete (permanent, no recycle bin).
